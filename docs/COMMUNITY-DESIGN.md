# 커뮤니티 고도화 설계안

작성: 2026-09-29. 상태: 1차 핵심 구현·웹 검증 완료. 저장·질문·알림은 후속 범위.

## 목표

운동을 마친 사람이 기록을 쉽게 공유하고, 다른 사람의 운동에서 도움을 얻고, 받은 반응을 확인하는 흐름을 만든다. 초기에는 참여자가 많지 않다고 가정한다. 실제 이용량·이탈률은 아직 측정하지 않았으며 아래 문제는 코드 구조에서 확인한 것이다.

## 현재 구현과 개선 이유

| 현재 | 개선 이유 |
|---|---|
| 오운완·인기·운동·루틴·내 글 5개 탭 | 콘텐츠 종류와 정렬, 개인 메뉴가 같은 깊이에 섞임 |
| 사진 필수, 한마디 200자 | 사진 없이 운동 기록만 공유하거나 질문하기 어려움 |
| 사진·티칭을 합친 최근 120개를 브라우저에서 분류 | 오래된 내 글·검색 결과 누락 가능. 인기는 전체 게시물이 아닌 최근 수집분 좋아요 순 |
| 진입 시 영상·루틴·루틴 적용 대상까지 조회 | 첫 화면에 필요 없는 조회도 진입 응답에 포함 |
| 사진 글 좋아요·댓글·수정·삭제·신고, 별도 영상·루틴 기능 | 기존 기능을 재사용할 기반이 있음 |
| 조사한 댓글 작성 액션에 알림 생성 없음 | 댓글 이후 작성자가 다시 돌아올 동선 필요 |

근거: `src/app/community/page.tsx`, `src/features/community/{data-access,feed,community,community-actions}.ts`, `src/features/community/components/community-board.tsx`.

## 화면 구조

기존 브랜드 머리글과 앱 하단 메뉴를 유지한다. 커뮤니티 콘텐츠 탭은 `피드 / 운동 영상 / 루틴`으로 정리한다. `내 활동`은 머리글 버튼으로 옮기고, 인기 선택은 피드의 정렬로 옮긴다. 기존 URL은 계속 접근 가능하게 매핑한다.

```text
짐꾼                         검색  내 활동
피드          운동 영상          루틴
전체 · 오운완 · 질문          최신순 ▾
───────────────────────────────────
오늘 운동을 공유해보세요       기록 선택
───────────────────────────────────
닉네임 · 작성시간 · 공개 범위        ⋯
운동 요약 / 사진 / 질문 본문
좋아요    댓글    저장
                              글쓰기
───────────────────────────────────
기존 앱 하단 메뉴
```

큰 홍보 배너·카드 속 카드·자동 재생 장식은 추가하지 않는다. 사진은 선택이며, 질문은 텍스트 위주로 높이를 줄인다. 운동 영상은 현재 릴스 화면을 유지한다. 그룹 전용 탭을 다시 만들지 않으며 공개 범위와 그룹명은 글에서 구분한다.

## 1차: 피드와 기록 공유

1. **피드 조회 개선**: 서버에서 유형·정렬·작성자·검색을 적용한 뒤 20개씩 가져온다. 최신순은 `(created_at, id)` 커서로 중복·누락을 막는다. 처음에는 더 보기 버튼을 제공하고 상세에서 뒤로 오면 필터·스크롤을 복원한다. 영상·루틴은 해당 탭 진입 시 조회하고 조회 결과를 재사용한다.
2. **운동 기록 공유**: 운동 완료 화면과 글쓰기에서 기록을 선택 → 운동명·완료 세트·운동시간 미리보기 → 한마디·선택 사진 → 공개 범위 → 게시. 실제 저장된 값만 사용하고 누락된 수치는 숨긴다. 체중·건강 메모 등은 자동 공개하지 않는다. 기록 없는 사진 인증도 유지한다.
3. **공유 데이터**: 게시 시점 요약을 저장해 원본 기록 수정·삭제가 기존 글을 바꾸지 않게 한다. 원본 기록 접근은 작성자에게만 허용한다. 공유 때문에 원본 운동 기록이나 영구 루틴을 변경하지 않는다. 중복 클릭·재시도는 같은 제출 ID로 처리한다.
4. **내 활동과 저장**: 내 글·댓글 단 글·저장한 글을 각각 서버 조회한다. 초기 120개 밖의 내 글도 찾을 수 있어야 한다. 삭제되거나 볼 권한이 없어진 글은 저장 목록에서도 숨긴다.
5. **검색과 인기**: 피드는 본문·운동명 검색, 영상은 기존 운동 태그 검색을 유지한다. 인기 v1은 최근 7일 안의 오운완 게시물에 대해 좋아요 수 → 작성시간 → ID 순으로 명확하게 정의한다. 조회 가능한 전체 후보에서 계산하고 페이지 이동 중 기준이 흔들리지 않도록 조회 기준시각을 유지한다. 개인화 추천은 후속으로 둔다.

1차에서는 질문 탭을 노출하지 않는다. 위 화면의 질문 필터는 2차 활성화 대상이다.

## 2차: 질문과 반응

- **질문 글**: 사진 없이 제목·본문·운동 태그로 작성한다. `답변 기다리는 질문` 필터와 작성자의 `해결됨` 표시를 제공한다. 좋아요 많은 질문만 노출되어 새 질문이 묻히지 않도록 한다.
- **댓글 알림**: 먼저 앱 내 알림으로 제공한다. 자기 댓글은 알리지 않고 중복 생성은 막는다. 클릭 시 해당 글·댓글로 이동하고, 삭제·권한 변경 시 안내한다. 이후 사용자 설정에 따라 푸시를 연결한다.
- **운영**: 기존 통합 어드민 신고 처리에 새 글 유형을 연결한다. 사용자 차단·신고 이후의 피드/검색/직접 링크 동작을 함께 정의한다. 차단 기능은 서버 조회와 접근 정책을 적용하는 단위로 출시한다.

팔로우·DM·주간 챌린지·개인화 추천은 초기 범위에서 제외한다. 게시물이 쌓이고 재방문이 확인된 뒤 별도 설계한다.

## 데이터와 구현 경계

- 기존 `community_posts`에 게시물 유형, 선택 사진, 운동 요약 스냅샷, 중복 제출 키를 추가하는 방안을 우선 검토한다. 기존 글은 사진 인증으로 유지한다. 사진 URL의 기존 NOT NULL 제약·타입·검증·상세 렌더를 같이 변경한다.
- 저장은 `(user_id, post_id)` 유일 제약을 갖는 별도 테이블로 관리한다. 영상·루틴 저장은 별도 대상 유형 설계가 필요하므로 1차 저장은 피드 글로 한정한다.
- 질문 제목·해결 상태, 커뮤니티 알림 이벤트는 2차 마이그레이션으로 분리한다. 기존 알림 저장소와 환경설정 재사용 가능 여부는 구현 전에 확인한다.
- 일반 조회는 사용자 세션과 RLS를 유지한다. 인기 집계·검색·저장·알림에서도 `전체 공개 / 그룹만 / 그룹 제외` 권한을 동일하게 적용한다. 관리자 조회는 일반 사용자 조회와 구분한다.
- 좋아요는 원하는 상태를 보내는 방식으로 중복 요청에 안전하게 만든다. 업로드 실패 시 작성 내용 유지, 게시 실패로 남은 업로드 정리, 사진 없는 글의 접근 가능한 상세 링크도 포함한다.
- 기존 운동·루틴 담기와 영상 재생 로직은 유지하면서 화면 진입과 조회만 단계적으로 정리한다.

## 완료 기준과 실행 순서

1. 조회·탐색: 최근 120개 밖의 내 글 검색, 페이지 중복 없음, 필터·뒤로 가기 상태 복원, 공개 범위별 접근 테스트.
2. 작성: 사진 없는 기록 공유, 기존 사진 인증, 중복 제출·업로드 실패 후 재시도, 원본 운동 기록 불변 테스트.
3. 저장: 저장/취소·재접속 유지, 타인 저장 목록 차단, 게시물 삭제·권한 변경 처리.
4. 화면: 320/390/430px·다크 테마·키보드 열린 작성 화면·하단 메뉴 겹침·Android 뒤로 가기 검증.
5. 2차: 질문 해결 상태·댓글 알림 중복 방지·알림 직접 링크·통합 어드민 신고 처리 검증.

개발 전 현재 피드 첫 응답과 전송량을 측정하고 변경 후 동일 조건으로 비교한다. 제품 지표는 공유 시작 대비 게시 성공률, 글별 댓글 발생 비율, 커뮤니티 재방문을 집계하되 본문·사진·건강 데이터는 분석 이벤트에 담지 않는다. 실제 수치 확보 전 목표 개선율을 단정하지 않는다.

권장 첫 구현 묶음: **피드 조회/탐색 + 운동 기록 공유 + 내 글 조회 개선**. 이후 저장, 질문·알림 순서로 진행한다.

## 1차 구현 결과 (2026-09-29)

피드·운동 영상·루틴 메뉴, 서버 검색/인기/내 글 조회, 20개 더 보기, 상세 왕복 복원, 사진 없는 운동 기록 공유와 중복 게시 방지, 완료 화면 공유 진입을 구현했다. 현재 개인 메뉴는 구현 범위에 맞춰 내 글로 유지한다. 공유 기록 선택은 최근 완료 기록 최대 500행에서 최대 30개 날짜를 제공한다. 인기는 조회 시작시각 기준 최근 7일 글을 대상으로 하며 좋아요 변경 시 순위가 바뀔 수 있다. 전체 자동 검증과 실기기·배포 상태는 로드맵 P1.C를 기준으로 한다.

최종 화면 조정: 사용자 피드백에 따라 내 글은 로고 줄이 아닌 피드·운동 영상·루틴과 동일한 상단 탭 줄에 배치한다. 위 초안의 머리글 개인 메뉴 배치는 이번 구현에 적용하지 않는다.
