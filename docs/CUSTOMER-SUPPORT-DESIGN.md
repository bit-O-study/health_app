# 고객센터·버그/불편 접수·운영자 카카오톡 알림 설계

작성/수정: 2026-09-25. 상태: 무료 고객센터 웹 구현·DB 적용·대상 자동 검증 완료. 카카오 최초 연결·실제 발송/Android·운영 배포는 대기. 운영 연결 절차는 CUSTOMER-SUPPORT-SETUP.md 참고.

## 1. 범위와 성공 기준

설정 → 고객센터에서 버그, 사용 불편, 기능 제안, 계정/기타 문의를 접수한다. 접수번호와 내 문의 내역을 제공하고, 관리자 고객센터에서 답변·처리한다. 새 문의는 운영자가 연결한 카카오 계정의 나와의 채팅으로 보낸다. 전화번호를 입력해 발송하는 방식이 아니며 고객센터 수신용 전화번호도 저장하지 않는다. 운영자 1명부터 시작한다.

성공 기준: 제출 한 번당 문의 한 건, 타인 열람 불가, 접수 성공과 발송 성공 구분, 관리자 답변이 해당 회원에게 표시, 알림 장애 중에도 접수 보존. 이번 요청은 설계 단계로 해석하며 아래는 구현 예정 계약이다.

## 2. 현재 구조와 연결

- `/admin/reports`: 게시물·댓글·루틴 콘텐츠 신고 및 모더레이션. 기존 용도로 유지.
- `/admin/events`: 개인정보를 제거한 자동 오류 관측. 고객 문의와 화면/버전/시간을 비교하는 참고 자료로 연결한다. 익명화된 집계를 특정 회원의 오류로 단정하지 않는다.
- `src/features/admin/admin.ts`: 고객 문의는 `isAdminUser`와 DB `is_admin()` 권한 사용. 콘텐츠 모더레이터나 트레이너에게 접근권을 주지 않는다.
- 기존 트레이너 SOLAPI 연동은 그대로 보존한다. 고객센터는 별도 카카오 나에게 보내기 어댑터를 사용하며 SOLAPI API를 호출하지 않는다. 기존 Web Push 구현은 운영자 기기 알림 보조 경로로 재사용한다.
- 현재 `vercel.json`은 일/주 단위 크론이다. 이것만으로 즉시 알림이나 분 단위 재처리를 보장할 수 없다.

## 3. 회원 화면

| 화면 | 구성 |
|---|---|
| `/support` | 버그 신고 / 불편 신고 / 기능 제안 / 기타 문의, 내 문의 내역, 짧은 도움말 |
| `/support/new` | 분류, 제목(1~100자), 내용(1~5000자), 선택 스크린샷 최대 3장, 진단정보 첨부 선택 |
| `/support/[id]` | 접수번호, 처리 상태, 대화 이력, 추가 설명, 해결 여부 확인/재문의 |

설정에 항상 고객센터 진입점을 둔다. 오류 화면에도 ‘문제 신고’를 제공하고 해당 화면 경로를 안전하게 전달한다. 홈 앱 추가 목록 등록은 후속 선택 범위다.

버그 양식은 ‘어디서 / 무엇을 했을 때 / 실제 결과 / 기대 결과’를 안내하되 긴 필수 항목을 늘리지 않는다. 첨부 실패 시 사진 재시도 또는 사진 없이 접수를 선택할 수 있다. 오프라인·서버 저장 실패에는 접수 완료를 표시하지 않고 작성 내용을 화면에 유지한다. 네트워크 응답이 끊겨 재전송해도 같은 client_request_id를 재사용한다.

진단정보는 첨부 여부와 포함 항목을 회원이 확인한다. 허용 항목은 쿼리·식별자 제거 경로, 앱 버전, OS/브라우저 종류, 화면 크기, 발생 시각, 정해진 오류 코드다. 토큰·쿠키·비밀번호·전체 콘솔 로그·운동/식단/신체 기록은 자동 수집하지 않는다. 스크린샷은 사용자가 직접 선택하고 미리보기/삭제 가능하며 자동 화면 캡처는 하지 않는다.

첫 버전 문의 생성은 로그인 회원 대상. 로그인 실패·정지 회원도 도움받을 수 있도록 로그인/정지 화면에는 공개 도움말과 실제 운영 문의 이메일을 제공한다. 현재 개인정보/계정삭제 페이지의 이메일 자리표시자도 실제 운영 연락처 확정 시 함께 교체한다. 비회원 웹 문의는 이메일 인증·스팸 방어를 갖춘 별도 후속 범위로 둔다.

## 4. 관리자 화면

`/admin/support`에 미확인 수 배지, 분류/상태/기간/담당자 필터, 접수번호/제목 검색, 페이지네이션을 둔다. 목록은 최근 접수와 미처리를 쉽게 확인하도록 구성한다. 화면이 보이는 동안에만 60초 간격 갱신과 수동 새로고침을 기본으로 하고, 별도 실시간 구독은 필요할 때 추가한다.

상세 `/admin/support/[id]`에는 원문·사진·진단정보·회원과의 답변·관리자 전용 메모·처리 이력·알림 발송 이력을 표시한다. 내부 메모는 회원에게 반환하지 않는다. 유사 문의 연결과 우선순위(일반/높음/긴급)는 관리자가 지정하며 사용자 선택만으로 긴급 알림을 발생시키지 않는다.

상태: 접수(new) → 확인 중(in_progress) → 회원 답변 대기(waiting_user) → 해결(resolved) → 종료(closed). 관리자 공개 답변은 자동 해결로 처리하지 않는다. 해결/종료된 문의에 회원이 재문의하면 확인 중으로 되돌린다. 미확인 여부는 처리 상태와 별도 읽음 시각으로 관리한다.

답변은 먼저 앱 내 문의함에 확실히 저장한다. 회원 답변 알림은 앱 내 미확인 배지 기본, 기존 푸시 동의 사용자는 후속 푸시 연동 가능. 회원에게 카카오톡을 보내는 기능은 이번 운영자 알림 범위와 구분한다.

## 5. 무료 운영 계약과 카카오 연결

추가 유료 서비스 가입·유료 알림톡·문자 발송·유료 큐는 사용하지 않는다. 카카오 Developers 무료 쿼터와 기존 호스팅/DB/스토리지의 남은 무료 용량 안에서 운영한다. 기존 인프라 전체 비용이 영구적으로 0원이라는 의미는 아니다. 배포 전 현재 요금제·공유 사용량·상업적 사용 조건을 확인하며, 무료 조건을 충족하지 않으면 자동 유료 전환하지 않고 제한을 보고한다.

카카오 공식 쿼터(2026-09-25 조회): 메시지 전송 앱당 하루 30,000건 외 발신자/수신자 각각 100건, 발신자-수신자 pair 20건 제한이 명시돼 있다. 나에게 보내기에 적용되는 계정별 실제 한도는 개발자 콘솔/실제 오류로 확인하며, 앱 전체 수치만 보고 무제한 발송으로 설계하지 않는다. 첫 버전은 보수적으로 운영자당 일 15회(테스트·재시도 포함) 시도 예산을 설정한다. 이는 공급자 한도 단정이 아닌 내부 상한이다. 다른 기능의 같은 카카오 앱 사용량도 공유되므로 공급자 쿼터 오류가 나면 즉시 중지한다. 예산 차감은 DB에서 원자적으로 처리하고 날짜 경계가 공급자와 다르면 최근 24시간 상한도 함께 적용한다.

수신 채널은 `POST https://kapi.kakao.com/v2/api/talk/memo/default/send`의 기본 텍스트 템플릿이다. 비즈니스 채널·알림톡 심사·전화번호·충전은 필요하지 않다. 필요한 설정은 카카오 로그인 활성화, 전용 리다이렉트 URI, 제품 링크 도메인, `talk_message` 동의항목과 운영자 동의다. 제한 상태의 앱이면 운영자를 앱 팀 멤버로 등록하는 등 실제 콘솔 조건을 먼저 확인한다.

관리자 설정 → ‘내 카카오톡 연결’ → 카카오 동의 → 연결된 계정 확인 → 테스트 보내기 순서로 진행한다. 일반 회원에게 메시지 동의를 요청하지 않는다. 기존 Supabase 로그인 세션과 독립된 운영자 OAuth 연결로 구현해 회원 로그인 scope와 콜백을 변경하지 않는다.

OAuth 시작·콜백 모두 관리자 권한을 확인한다. 짧은 수명의 일회용 state를 서버 관리자 세션에 바인딩하고 state 재사용/다른 세션 콜백을 차단한다. 인가코드는 서버에서 교환하며 토큰은 서버 전용 암호화 저장소에 보관한다. DB 토큰 행은 브라우저 역할에 SELECT를 허용하지 않고, 암호화 키는 DB와 별도 서버 환경변수로 관리한다. 클라이언트·로그·URL에 토큰을 노출하지 않는다.

액세스 토큰은 만료 전/명확한 만료 응답 시 갱신한다. 갱신은 계정별 잠금으로 중복 실행을 막는다. 새 refresh_token이 반환될 때만 교체하고 반환되지 않으면 기존 값을 유지한다. 응답의 만료 시각으로 관리하며 영구 유효를 가정하지 않는다. 철회·refresh 만료 시 `needs_reconnect`로 바꾸고 어드민 및 동의된 앱 푸시로 재연결을 안내한다. 문의가 드문 경우 기존 일일 유지 작업에서 임박 만료를 점검하되 실패 시 무한 재시도하지 않는다. 연결 해제/관리자 권한 상실은 예약 발송을 차단하고 저장 토큰을 삭제한다. 공유 카카오 앱의 로그인 연결까지 끊는 전역 unlink를 함부로 호출하지 않는다.

메시지 예시:

> [헬쑤 고객센터] 새 문의가 접수되었습니다.
> 접수번호: CS-1234 / 분류: 버그 신고
> 관리자 화면에서 확인해 주세요.
> 버튼: 문의 확인

버튼은 등록된 운영 도메인의 관리자 상세 화면으로 연결한다. 인증 우회 토큰 없이 로그인과 관리자 권한을 요구한다. 자유 입력 제목/본문·회원 식별정보·사진은 메시지에 넣지 않는다.

신규 문의는 예산 내에서 즉시 발송을 시도한다. 추가답변은 카카오 건별 발송 대신 미확인 배지와 다음 요약 대상으로 둔다. 예산 초과 문의는 어드민에 전부 보존하고 다음 허용 실행에서 ‘미확인 문의 N건’ 요약 한 건으로 묶는다. 오래된 접수 알림을 다음 날 개별로 모두 재발송하지 않는다. 관리자가 이미 처리한 문의는 요약에서 제외한다. 첫 버전은 지연될 수 있는 무료 방식이며 매 문의의 즉시 카카오 수신을 보장하지 않는다.

나와의 채팅 메시지 도착만으로 휴대폰 알림음·잠금화면 배너를 보장하지 않는다. 사용자 기기의 카카오 동작을 실제 확인한다. 즉시 기기 알림 보완은 기존 Web Push를 운영자 명시 동의 후 사용한다. 푸시가 미설정/차단돼도 어드민 문의함은 항상 남으며 유료 문자로 전환하지 않는다.

## 6. 저장·발송 흐름 및 장애 처리

1. 서버에서 로그인·입력·빈도 제한 검증. `(user_id, client_request_id)` 유일키로 제출 재시도를 한 건으로 처리한다.
2. 단일 DB 트랜잭션/RPC로 문의·첫 메시지·outbox를 저장한다. 접수 완료 여부는 이 커밋으로 결정한다.
3. 커밋 후 응답을 반환하고 Next.js의 지원되는 응답 후 처리 기능으로 짧은 발송 시도를 수행한다. 구현 시 공식 프레임워크/배포 런타임 지원 및 실행시간을 검증한다. 무보호 fire-and-forget fetch를 사용하지 않는다. 응답 후 작업 자체는 내구성 큐가 아니므로 outbox를 원본으로 삼는다.
4. 조건부 claim/lease로 중복 워커를 차단하고 관리자 자격·연결·예산을 다시 검사한다. 현재 일일 크론에 제한된 복구 배치를 연결하고 관리자 ‘대기 알림 처리’도 제공한다. 유료/분 단위 스케줄러를 요구하지 않는다. 즉시 작업이 유실되면 일일 복구까지 늦어질 수 있다.
5. 상태: queued → processing → api_succeeded 또는 failed. 카카오 result_code=0만 API 성공으로 기록한다. 휴대폰 수신/읽음 상태인 delivered/read는 만들지 않는다. 이 API에 SOLAPI식 배달 콜백이나 결과 조회가 있다고 가정하지 않는다.
6. 연결 미완료/철회는 needs_reconnect, 로컬/공급자 한도는 quota_deferred, 네트워크 타임아웃/프로세스 중단 후 발송 여부 불명은 unknown으로 남긴다. unknown 및 만료된 processing은 자동 재발송하지 않는다. 관리자 수동 재전송에는 중복 가능성을 표시하고 이력을 남긴다.
7. 명확한 토큰 만료에만 갱신 후 한 번 재시도한다. 확실한 미전송 일시 오류만 다음 복구 실행에서 제한적으로 재시도한다. 한도 오류는 정해진 이후로 미루고 무조건 빠른 재시도하지 않는다. 모든 시도는 내부 예산에 포함한다.
8. 이미 처리된 문의·해제된 연결의 작업은 취소한다. 재연결 후 누적분은 원문 개별 발송 대신 미확인 요약으로 합친다. 접수 실패와 알림 실패를 화면에서 분리한다.

동일 알림 고유키 `(event_id, recipient_id, channel)`와 요약 대상 이벤트 연결을 두어 동시 요약/개별 처리 중복을 막는다. 문의 빈도 초기안은 계정별 분당 3건·일 20건이며 서버/DB에서 원자적으로 검증한다. 첨부/추가답변도 별도 한도를 적용한다.

무료 인프라 보호: 이미지 원본 최대 5MB는 서버 검증 뒤 긴 변 1600px 이하·저장 목표 500KB 이하로 재인코딩하고 최대 3장을 허용한다. 초기 고객센터 첨부 총량 상한은 100MB와 실제 남은 무료 공간 중 작은 값으로 정하며 동시 업로드 예약량도 계산한다. 여유량을 안전하게 확인할 수 없으면 첨부만 중지하고 텍스트 접수를 우선한다. 삭제 기간·업로드 고아 정리와 페이지네이션을 적용한다. DB/실행/전송량도 기존 프로젝트 전체 사용량과 함께 감시하고, 전체 DB 한도에 도달하면 접수 성공으로 속이지 않고 운영 문의 이메일을 안내한다.

회원은 자기 문의와 공개 메시지·첨부만 조회한다. 생성/추가답변/상태 전환은 제한된 RPC로 수행하고 user_id는 auth.uid()에서 결정한다. 회원이 임의 status/assignee/notification destination을 덮어쓰지 못한다. 관리자는 관리자 권한 RPC로 처리하며 UI 숨김 외에 RLS·스토리지 정책까지 검증한다. 트레이너와 콘텐츠 모더레이터에게는 권한이 없다.

첨부는 private bucket, JPEG/PNG/WebP만, 파일당 5MB·최대 3개를 제안한다. 서버에서 실제 포맷/크기 검증, 재인코딩으로 EXIF 제거, SVG/HTML 거절. 짧은 만료의 서명 URL은 열람권 검사 후 발급한다. 미완성 업로드는 24시간 후 정리하고 저장된 파일 총량도 제한한다.

보존 정책 제안: 종료 후 문의 180일, 사진/진단정보 30일, 발송 기술 로그 30일. 이는 법정 기간 단정이 아닌 제품 운영 기본안이며 공개 정책과 운영 필요를 확정한 후 적용한다. 탈퇴 시 작성자 식별정보와 첨부 삭제/익명화 및 보존 예외를 명시한다. 회원 메모나 신고 원문을 서버 로그에 복제하지 않는다.

## 8. 구현 순서와 검증

1. 문의/답변/비공개 첨부/관리자 화면과 RLS. 다른 회원·트레이너·콘텐츠 모더레이터 접근 차단, 중복 제출, 내부 메모 비공개 검증.
2. 운영자 전용 카카오 OAuth 연결·암호화 저장·갱신·해제. state 위조/재사용, 콜백 시 권한 상실, 다른 계정 연결, 갱신 토큰 미반환·회전·철회 회귀.
3. 무료 발송 어댑터/outbox/일일 복구/요약/동의된 푸시. 중복 워커, 예산 경합, 429/쿼터 오류, 타임아웃 후 중복 금지, 연결 해제, 무료 용량 초과 및 유료 API 호출 없음 검증.
4. 모바일 E2E: 접수→관리자 답변→회원 재문의, 첨부 실패/텍스트만 저장, 토큰 브라우저 비노출, 다크모드·320px·로그인 복귀. 새 설정은 테스트 어댑터로 외부 메시지 없이 검증.
5. 사용자가 연결한 카카오 계정으로 테스트 1건. 나와의 채팅 도착과 기기 배너/소리 각각 확인, 필요 시 동의된 Web Push 수신 확인. 미설정/한도/철회 시 문의 보존 확인.

예정 파일: 기존 고객센터 설계의 화면/DB에 `src/features/support/kakao.server.ts`, 관리자 OAuth 시작/콜백 경로, 기존 일일 유지 작업의 제한 배치, 단위/DB/E2E를 추가한다. 기존 회원 로그인과 트레이너 유료 발송 코드는 변경하지 않는다.

필요한 사용자 작업은 운영자 카카오 계정 연결·메시지 동의, 기기 알림 테스트다. 개발 설정은 REST API 키·필요한 client secret·등록 콜백/링크 도메인·서버 암호화 키 및 실제 운영 문의 이메일이다. SOLAPI 가입/충전·비즈니스 채널·알림톡 승인·전화번호 등록은 고객센터에 필요하지 않다.

## 9. 조사와 검증 기록

## 구현 검증 결과 (2026-09-25)

문의 접수/답변/메모/처리·재문의, 사진 비공개 업로드·다운로드·삭제, 관리자 무료 카카오 연결과 대기열·일일 복구를 구현했다. 사진은 최초 접수 후 상세 화면에서 첨부한다. 진단 첨부는 기기 종류·빌드·화면 크기만 허용한다. 단위 23개·DB 롤백 1개·운영 빌드 모바일 Chromium 1개(55.3초), 대상 lint/type/build 통과. 실제 카카오 발송과 기기 알림은 수행하지 않았다. 위 설계 중 운영 환경 검증은 대기이며 과거 조사 시점의 미구현 기록과 구분한다.
