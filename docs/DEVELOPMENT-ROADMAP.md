# 헬쑤 개발 로드맵 — 업무 기준 문서

> 개발 전에 `docs/원칙.md`와 이 문서를 순서대로 읽는다. 진행 상황은 이 문서의 상태와 하위 업무로 관리한다.

## 운영 규칙

- 상태는 `[대기]`, `[진행중]`, `[완료]`, `[보류]`만 사용한다.
- 구현 중인 대항목은 원칙적으로 하나만 `[진행중]`으로 둔다.
- 시작 전에 조사·구현·자동 테스트·실기기 검증을 하위 업무로 구체화한다.
- 최신 검증 근거가 있어야 `[완료]`로 바꾼다. 실기기/운영 확인이 남으면 완료가 아니다.
- 새 업무는 가장 가까운 항목 아래에 추가하고 사용자 미커밋 변경은 보존한다.

    ③ 맨몸(무게 0)은 볼륨 0 (`progress.ts` 머리말)
- [완료] 운동별 중량·횟수·세트 이력과 주간 총 볼륨
  - `exerciseHistory()` — 날짜별 한 줄(같은 날 두 번이면 세트는 합, 무게는 최고치).
    세트별 기록이면 **가장 무거운 세트**를 대표값으로
  - `weeklyVolumeSeries()` — 주(월요일) 단위. 일별 그래프는 운동한 날/쉰 날이
    번갈아 톱니처럼 보여 추세가 안 보인다

  - 1RM 은 세트 중 최고치 — 드롭세트에서 마지막(가벼운) 세트를 쓰면 힘이 낮게 잡힌다

### 2.2 [진행중] 규칙 기반 점진적 과부하 추천

- [완료] 운동 유형별 증량 단위와 예외 규칙 정의
  - 증량 단위는 강도 등급으로 — 복합 고중량 5kg / 덤벨·머신 2.5 / 고립 1.25
    (`weightStepKg`). 제안 무게는 항상 단위의 배수로 맞춘다 — 2.5kg 원판에
    1.7kg 같은 값을 권하면 못 든다
  - 예외 둘: **맨몸**(무게로 못 올린다 → 횟수), **시간 종목**(홀드 → 버티는 시간).
    둘 다 `bodyweight` 로 갈라 무게 제안을 아예 안 한다
- [완료] 목표 반복 달성 시 증량, 하락 시 유지 추천
  - 목표 횟수는 `prescription.targetReps()` — **처방과 같은 기준**을 본다.
    여기가 갈라지면 계획은 10회를 시키는데 추천은 12회를 기다리게 된다
  - 채웠으면 한 단계 증량, 못 채웠으면 무게는 그대로 두고 횟수부터
    (무게를 또 올리면 자세가 무너진다)
- [완료] 장기 정체 시 볼륨 감소 또는 휴식 추천
  - `stalledSessionCount()` — 최고 추정 1RM 이 갱신되지 않고 이어진 세션 수
  - 3세션 정체 → **디로드**(−10%, 증량 단위로 반올림) / 5세션 → **휴식 권장**
  - 디로드는 증량보다 우선한다 — 목표를 채웠더라도 정체가 더 급한 신호다
- [완료] 추천 근거·사용자 선택권 표시 및 단위 테스트
  - 모든 결과에 한국어 `reason` 이 붙는다("지난번 100kg × 6회로 목표(6회)를
    채웠어요. 105kg 로 올려요") — 숫자만 던지면 따를지 무시할지 판단을 못 한다
  - 성장 그래프 종목 카드에 표시. 섹션 머리에 "제안이며 그대로 따르지 않아도
    된다" 를 명시
  - 단위테스트 16개(`overload.test.ts`), E2E 2개(증량 근거·디로드)
- [완료] 2.1 에서 만든 `nextWeightAdvice` 를 이 규칙으로 **흡수**(중복 제거)
  — 추천이 두 군데면 화면마다 다른 무게를 권하게 된다
- [완료] 운동모드/계획 편집에서도 추천 노출 — 무게를 정하는 그 순간에 보이는 게
  가장 쓸모 있다. 성장 그래프에만 있으면 정작 정할 때는 안 보인다
  - 화면값 변환은 `overload-advice.ts` 한 곳에서(`toAdvice`·`buildAdviceMap`) —
    화면마다 따로 그리면 같은 판단에 다른 말머리·다른 색이 붙는다.
    표시도 공용 `OverloadHint` 하나(성장 그래프도 이걸로 갈아탐)
  - **'적용' 버튼** — 읽고 손으로 옮겨 적게 두지 않는다. 다만 값을 넣는 건 언제나
    사용자가 누를 때만(제안이 값을 몰래 바꾸면 그건 추천이 아니다).
    넣을 값이 없는 '휴식 권장'·세트별 기록 줄에는 버튼을 안 단다
  - 운동모드: 서버(`today-exercises`)가 큐에 실어 보낸다. 근거가 되는 완료 기록은
    미리채움이 쓰던 조회를 `getRecentDoneRecords` 로 합쳐 **왕복이 안 늘었다**
    (겸사겸사 `set_details` 를 같이 읽어 드롭세트도 제대로 센다)
  - ⚠ 목표 횟수는 **미리채움 전** 계획값으로 본다. 지난번 실제 횟수를 목표로 넘기면
    "지난번 = 목표" 가 되어 매번 증량이 걸린다(스스로를 만족시키는 목표)
