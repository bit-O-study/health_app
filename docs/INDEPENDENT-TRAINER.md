# 독립 헬스 트레이너 설정 (2026-09-25)

그룹 가입/그룹장 권한과 트레이너 관리는 독립적이다. 기존 그룹원은 자동으로 트레이너 회원이 되지 않는다.

## 이용 흐름

1. 설정 → 트레이너 정액권에서 트레이너 이름과 알림 수신 번호로 등록 신청.
2. 관리자 → 트레이너 이용권에서 결제 확인 후 시작일·종료일·회원 수 승인.
3. 활성 기간에만 홈/하단 앱 선택에 헬스 트레이너 앱 표시. 명시적으로 부여한 무제한 이용권은 종료일을 PostgreSQL `infinity`로 저장하며, 화면에는 무제한으로 표시한다. 회원 수 한도와 해지 처리는 동일하다.
4. 회원 휴대폰 번호와 알림톡/문자 선택 → 7일 유효 초대.
5. 로그인한 회원이 항목별 공유 범위를 선택하고 명시적으로 수락해야 연결됨. 초기 체크는 모두 꺼짐.
6. 설정 → 트레이너 연결에서 공유 변경/연결 삭제. 삭제 즉시 조회·처방 권한 차단, 알림톡은 별도 대기열.

기존 그룹 기반 트레이너 URL은 독립 앱으로 이동하며 예전 RPC 실행 권한은 폐쇄한다. 기존 그룹과 과거 코멘트는 삭제하지 않는다.

## 실제 메시지 발송 설정

서버 환경변수에 아래 키를 설정한다. 비밀값을 저장소에 넣지 않는다.

- `SUPABASE_SERVICE_ROLE_KEY`: 서버의 알림 대기열 처리용
- `NEXT_PUBLIC_SITE_URL`: 초대 링크가 열릴 배포 앱 주소
- `SOLAPI_API_KEY`, `SOLAPI_API_SECRET`
- `SOLAPI_FROM`: 승인된 문자 발신번호
- `SOLAPI_PFID`: 카카오 채널 프로필 ID
- `SOLAPI_INVITE_TEMPLATE_ID`: `#{트레이너}`, `#{초대링크}` 변수 포함 승인 템플릿
- `SOLAPI_DISCONNECT_TEMPLATE_ID`: `#{트레이너}`, `#{회원}` 변수 포함 승인 템플릿

SOLAPI를 작업 가정으로 구현했다. 실제 사용 업체가 다르면 어댑터 변경이 필요하다. [공식 알림톡 문서](https://solapi.com/developers/api/messages-ata), [인증 및 발송 예제](https://solapi.com/blog/tutorial-script).

미설정 시 발송 성공으로 표시하지 않고 `queued`로 보존한다. 관리자 화면에서 설정 후 발송 재시도 가능. 동일 건은 조건부 상태 변경에 성공한 요청 하나만 발송한다. 타임아웃/불명확한 응답은 `unknown`으로 두고 자동 재발송하지 않는다. 프로세스 종료로 `processing`에 남은 경우도 업체 내역 확인 후 처리해야 한다. 업체 `submitted`는 발송 접수이며 최종 수신 완료는 아니다. 카카오 실패 시 문자로 임의 대체하지 않는다.

실제 알림톡 수신은 채널·승인 템플릿·발송 자격증명이 제공된 후 확인해야 한다. 테스트는 DB 롤백과 가짜 계정을 사용하며 실제 번호로 발송하지 않는다.

- `tests/be/trainer-access.test.ts`: 트랜잭션 안에서 마이그레이션과 가짜 계정을 만들고 전부 롤백. 승인/기간/동의/조회/공유/해제/대기열/예전 RPC 차단 검증.
- `tests/be/logic/trainer-invitations.test.ts`: 수신번호, 동의 값, 템플릿 변수, 발송 설정 누락, 하단 앱 저장값.
- `tests/e2e/independent-trainer.spec.ts`: 실제 앱 등록→초대 수락→공유 OFF→삭제. 발송 설정 없는 테스트 서버에서만 실행.
