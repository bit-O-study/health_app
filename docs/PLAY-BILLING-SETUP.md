# 구글 플레이 인앱결제 설정 — 로드맵 7.1

코드는 다 들어갔다. 여기 적힌 것은 **Play Console·환경변수처럼 코드로 못 하는 준비**다.
순서대로 하면 되고, 각 단계마다 "안 하면 어떻게 되는가"를 같이 적었다 — 빠뜨렸을 때
증상만 보고는 원인을 짐작하기 어려운 것들이라서다.

## 0. 전체 그림

```
앱(PlayBillingPlugin)  ──구매 토큰만──▶  서버(verifyPurchaseAction)
                                            │
                                            ├─▶ 구글 Play Developer API 로 직접 조회
                                            ├─▶ subscriptions 테이블에 저장(서비스 롤)
                                            └─▶ 수령 확인(acknowledge)
```

**앱이 하는 말은 아무것도 안 믿는다.** 앱은 토큰만 건네고, 상태·만료일은 서버가
구글에 물어본다. 앱을 뜯어 고쳐도 프리미엄이 되지 않는다.

## 1. Play Console — 구독 상품 등록

`수익 창출 → 구독 → 구독 만들기`

| 항목 | 값 |
|---|---|
| 상품 ID | `helssu_premium_monthly` |
| 기본 요금제 | 월 자동 갱신 |

⚠ **상품 ID 는 `src/features/billing/products.ts` 의 `PREMIUM_PRODUCT_ID` 와 글자 하나까지
같아야 한다.** 다르면 결제창이 뜨지 않고 앱에는 "상품 정보를 불러오지 못했어요" 만 보인다
(앱 쪽에서는 원인이 안 보인다).

만들고 나서 **활성화**까지 해야 한다. 초안 상태면 조회가 빈 목록으로 온다 —
증상이 "id 가 틀렸을 때"와 똑같다.

## 2. Play Console — 서비스 계정 만들기

서버가 구글에 물어보려면 자격 증명이 필요하다.

1. Google Cloud Console 에서 서비스 계정 생성 → **JSON 키** 다운로드
2. Play Console `사용자 및 권한 → 새 사용자 초대` 에 그 서비스 계정 이메일 추가
3. 권한에서 **재무 데이터, 주문 및 구독 설문 응답 보기** 를 켠다

⚠ 3번을 빼먹으면 조회가 401/403 으로 떨어진다. 우리 코드는 그걸 "못 물어봤다"로
처리해서 **기존 권한을 뺏지 않는다** — 즉 조용히 아무 일도 안 일어난 것처럼 보인다.
새 구독이 계속 "확인할 수 없어요" 로 끝나면 이 권한부터 확인할 것.

## 3. 환경변수 (Vercel + 로컬 `.env.local`)

| 이름 | 값 | 없으면 |
|---|---|---|
| `GOOGLE_PLAY_SERVICE_ACCOUNT` | 2번 JSON **파일 내용 전체**를 한 줄 문자열로 | 구독 화면이 "준비 중" 으로만 보인다 |
| `GOOGLE_PLAY_PACKAGE_NAME` | `app.helssu.twa` | 같음 |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase 프로젝트 설정의 service_role 키 | 검증은 되는데 **저장이 안 된다** ("구매는 확인했지만 저장하지 못했어요") |

`SUPABASE_SERVICE_ROLE_KEY` 가 필요한 이유: `subscriptions` 테이블에는 **사용자 쓰기
정책이 없다**(일부러). 사용자가 직접 쓸 수 있으면 스스로 프리미엄이 되기 때문이다.
그래서 서버만 쓸 수 있는 열쇠가 있어야 한다.

세 개 중 하나라도 없으면 `billingSetup().ready` 가 false 가 되고, 구독 화면은
**오류가 아니라 "준비 중"** 으로 안내한다(설정이 안 된 걸 오류로 보여주면 사용자가
자기 잘못인 줄 안다).

## 4. 앱 빌드

이미 코드에 들어가 있다 — 확인만.

- `android/variables.gradle` → `billingVersion = '7.1.1'`
- `android/app/build.gradle` → `com.android.billingclient:billing:$billingVersion`
- `AndroidManifest.xml` → `<uses-permission android:name="com.android.vending.BILLING" />`
  (없으면 결제창이 **아예 안 뜬다**)
- `MainActivity.onCreate` → `registerPlugin(PlayBillingPlugin.class)`
  ⚠ `super.onCreate` 보다 **먼저**. 뒤에 두면 브리지가 이미 만들어진 뒤라 웹이 플러그인을
  못 찾는다(웹에는 "앱을 최신 버전으로 업데이트해 주세요" 로 보인다).

⚠ 결제는 **Play 스토어를 통해 설치된 앱**에서만 동작한다. `adb install` 로 넣은
디버그 APK 에서는 결제창이 안 뜬다 — 내부 테스트 트랙에 올려서 테스트해야 한다.

## 5. 실기기 테스트

1. Play Console `설정 → 라이선스 테스트` 에 테스트 계정(구글 계정) 추가
   → 실제 결제 없이 결제 흐름 전체가 돈다
2. 앱을 **내부 테스트 트랙**에 올리고 그 계정으로 설치
3. 확인할 것
   - 결제 → 구독 화면이 '프리미엄' 으로 바뀌는가
   - 결제창을 그냥 닫으면 → 오류 문구가 **안 뜨는가**(취소는 오류가 아니다)
   - 앱 삭제 후 재설치 → **구매 복원** 버튼으로 다시 프리미엄이 되는가
   - Play 스토어에서 해지 → 남은 기간 동안 계속 프리미엄, 만료 후 무료
   - 라이선스 테스트는 갱신 주기가 짧다(월 구독 → 5분). 만료 동작을 빨리 볼 수 있다

## 6. 남은 것 — RTDN(실시간 개발자 알림)

지금은 **앱을 열 때 재검증**하는 방식이다. 그래서 갱신 직후 앱을 안 열면 잠깐
만료로 보일 수 있다(권한 계산이 만료 시각 기준이라 안전한 쪽으로 틀린다).

제대로 하려면 Play Console → 수익 창출 설정 → 실시간 개발자 알림에 Pub/Sub 주제를 걸고,
그 푸시를 받는 웹훅을 만들어 `subscriptions` 를 갱신해야 한다. 그때는 웹훅이
**구글이 보낸 것인지 검증**하는 일이 핵심이 된다(아무나 POST 하면 남의 구독을 조작할 수 있다).

## 7. 문제가 생겼을 때 보는 곳

| 증상 | 먼저 볼 것 |
|---|---|
| 결제창이 안 뜬다 | BILLING 권한 / Play 스토어 설치본인지 / 상품 활성화 여부 |
| "상품 정보를 불러오지 못했어요" | 상품 ID 오타, 상품이 아직 초안 |
| "구독 기능이 아직 준비 중이에요" | 환경변수 3개 |
| "구글 플레이에서 이 구매를 찾지 못했어요" | 패키지명이 다르거나 다른 앱의 토큰 |
| 계속 "확인할 수 없어요" | 서비스 계정의 **재무 데이터 보기** 권한 |
| 며칠 뒤 자동 환불됐다 | 수령 확인(acknowledge)이 실패하고 있다 — 서버 로그 확인 |
