다짐 — 하루 약속과 주간 리듬

지금 다짐은 “4주 동안 12일 운동하기” 같은 기간 목표입니다. 그런데 사람이 실제로 지키는 단위는 하루이고, 무너지는 단위는 주입니다. 이 보고서는 다짐을 “오늘 지킬 세 가지” + “이번 주 며칠” 두 층으로 다시 짭니다. 설문·판정·알림·종료까지 한 번에 새로 설계했습니다.

범위 다짐 기능 전면 작성 2026-09-25 예시 계정 여성 · 고급 · 96.7kg · 감량(68kg) · 권장 2,650kcal · 주 5일 루틴

1. 무엇을 만드는가

다짐 하나는 이 세 가지로 이루어집니다. 그 외에는 아무것도 없습니다.

층내용사용자가 보는 곳

왜 3개인가. 지금 설문은 미션을 8개까지 켤 수 있습니다. 그러면 “5개 중 3개 했으니 60%” 같은 숫자가 나오는데, 이 숫자는 무엇을 안 했는지를 감춥니다. 3개면 “하나 남았다”가 바로 읽힙니다.

왜 주 단위인가. 하루 놓친 게 곧 실패로 보이면 사람은 그날로 그만둡니다. 주 5일이 목표면 이틀은 놓쳐도 되는 날이 되고, 놓친 다음 날 복귀할 이유가 남습니다.

2. 지금 것의 문제

코드를 읽고 확인한 것만 적습니다. 1·2번이 “오늘 쓸 수 없다”의 직접 원인입니다.

1 · 높음

홈 카드에서 체크할 수 없다

카드 전체가 /commitments 링크입니다. 오늘 할 일을 보여주면서 그 자리에서 끝낼 수 없습니다.

2 · 높음

앱이 기록하지 못하는 다짐은 만들 수 없다

미션 10종이 전부 운동·식단 기록 기반입니다. 물·술·수면·스트레칭 같은 가장 흔한 다짐이 빠집니다.

3 · 높음

하루 실패가 곧 전체 실패로 보인다

캘린더가 매일 ○△✕ 만 찍습니다. 놓친 날을 만회할 주간 개념도, 유예도 없습니다.

4 · 중간

설문이 사용자가 모르는 숫자를 묻는다

“유산소 몇 분”, “단백질 몇 g”, “섭취 상한 몇 kcal”. 게다가 목표는 온보딩에서 이미 받은 값입니다.

5 · 중간

휴식일에도 ✕ 가 찍힌다

계획대로 쉰 날이 실패로 보이면 마커 자체를 믿지 않게 됩니다.

6 · 낮음

부분 진행이 보이지 않는다

판정이 boolean 이라 “운동 3개” 미션이 1개 했을 때와 0개일 때가 화면에서 같습니다.

7 · 낮음

리마인더도, 끝맺음도 없다

하루 단위 약속인데 그날이 가기 전 알려주지 않고, deadline 이 지나도 결과를 말해 주지 않습니다.

3. 설계 원칙

  1. 이미 아는 건 묻지 않는다. 성별·경력·체중·목표·주당 운동일은 온보딩과 루틴에 있습니다.
  2. 숫자는 묻지 않고 제안한다. 사용자는 생활을 답하고, 앱이 kcal·g·분으로 옮깁니다.
  3. 하루에 세 개까지. 많아지면 달성률이 희석되고 무엇을 안 했는지가 가려집니다.
  4. 놓친 날을 설계에 포함한다. 주간 목표와 유예권 — 완벽을 요구하지 않습니다.
  5. 모든 숫자에 이유를 붙인다. 근거 없는 목표는 지켜지지 않습니다.

4. 다짐 한 개의 구조

기존 commitments 행을 그대로 쓰되 네 칸을 더합니다(주간 목표·유예·알림 시각·강도). 미션에는 id 를 붙입니다 — 순번으로 가리키면 사용자가 미션을 지웠을 때 과거 체크가 다른 미션에 붙습니다.

9.2 연속으로 놓쳤을 때

이틀 연속 ✕ 면 다음 날 홈 카드 위에 한 줄이 뜹니다 — “이번 주 이틀 놓쳤어요. 목표를 조금 낮출까요?”
자동으로 낮추지 않습니다. 사용자가 고릅니다: 미션 하나 빼기 · 주 4일로 · 그대로 간다. 말없이 목표가 내려가면, 지켜도 지킨 것 같지 않습니다.

  add column if not exists weekly_target int not null default 5
    check (weekly_target between 1 and 7),
  add column if not exists rest_pass_per_week int not null default 1
    check (rest_pass_per_week between 0 and 3),
  add column if not exists remind_at time,            -- null = 알림 없음
  add column if not exists intensity text not null default 'normal'
    check (intensity in ('light','normal','hard'));

-- 2) 수동 체크와 '오늘 쉼'
create table if not exists public.commitment_days (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references auth.users(id) on delete cascade,
  commitment_id uuid not null references public.commitments(id) on delete cascade,
  for_date date not null,
  -- 체크한 수동 미션 id 목록. 자동 미션은 여기 넣지 않는다.
  checked_ids text[] not null default '{}',
  rest_pass boolean not null default false,   -- '오늘 쉼'
  created_at timestamptz not null default now(),
  unique (user_id, commitment_id, for_date)
);
create index if not exists commitment_days_lookup
  on public.commitment_days (user_id, commitment_id, for_date desc);

하루 한 행으로 잡은 이유: 수동 체크와 ‘오늘 쉼’은 같은 하루에 대한 사용자의 선언이라 함께 읽히고, 캘린더가 한 달치를 한 번에 가져갑니다. 자동 판정은 저장하지 않습니다 — 기록이 수정되면 결과도 바뀌어야 하므로 매번 계산합니다.

14. 리스크

  • 홈은 지금 다른 세션이 재작성 중입니다. 그래서 홈 카드를 6번째로 미뤘습니다.
  • 판정 규칙이 바뀌면 과거 캘린더의 모양이 바뀝니다. 이미 찍힌 ○△✕ 가 새 규칙(3개 기준)으로 다시 계산됩니다.
  • 수동 체크는 거짓말이 가능합니다. 그래서 화면에서 자동/수동을 구분해 두고, 성적표에서도 나눠 보여줍니다.
  • 기존 다짐 데이터는 미션에 id 가 없습니다 — 읽을 때 순번으로 m{n} 을 부여해 채웁니다.

15. 결정이 필요한 것

Q1. 과거 날짜도 체크할 수 있게 할까요?

어제 한 걸 오늘 체크하는 건 흔한 요구지만 무제한이면 기록이 의미를 잃습니다. 권장: 어제까지만 — 캘린더에서 그날을 눌러 체크.

Q2. ‘오늘 쉼’은 주 몇 회까지?

많으면 다짐이 헐거워지고, 없으면 아픈 날이 곧 실패입니다. 권장: 주 1회 · 설문에서 바꾸지 않고 고정

Q3. 과거 캘린더를 새 규칙으로 다시 그릴까요?

일관성은 얻지만 “어제까지 ○ 였던 날이 △ 가 되는” 일이 생깁니다. 권장: 새 다짐부터 적용 · 지난 다짐은 그대로

Q4. 미션 3개 제한을 강제할까요?

4~5개를 원하는 사용자도 있습니다. 권장: 설문은 3개로 만들되, 다짐 화면에서 직접 5개까지 추가 허용
