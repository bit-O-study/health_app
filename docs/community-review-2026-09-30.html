커뮤니티 탭: 지금 되는 것, 바로 막아야 할 것, 더할 것

커뮤니티 탭(피드 · 운동 영상 · 루틴)의 화면 코드, 서버 동작, 데이터베이스 권한 규칙을 점검했습니다. 기능은 꽤 갖춰져 있지만, 신고와 글쓴이 정보가 조작될 수 있는 구멍이 먼저 막혀야 합니다. 코드는 아직 바꾸지 않았습니다.

  • 글쓰기: 운동 기록 카드 붙이기(무게·메모는 일부러 빼서 공유), 사진, 공개 범위 3가지, 두 번 눌러도 한 번만 올라감

  • 루틴 신고는 저장이 안 됩니다. 허용된 신고 종류 목록에 루틴이 빠져 있습니다.

바로 고칠 것: 보안

신고 조작으로 엉뚱한 사람이 정지되는 흐름

누군가 A 의 글을 신고→신고 요청에 ‘대상 사용자 = B’ 로 바꿔 보냄→그대로 저장→관리자가 ‘정지’ 누름→B 가 정지됨

관리자 화면의 정지 버튼은 신고에 저장된 대상 사용자를 씁니다. 루틴 신고만 서버가 직접 찾아 넣고, 글·댓글·영상 신고는 앱이 보낸 값을 믿습니다.

1

신고 대상을 서버가 직접 찾아 넣기

지금은 글·댓글 신고의 대상 사용자·작성자·미리보기를 앱이 보낸 그대로 저장합니다. 조작된 신고 하나로 관리자가 엉뚱한 사람을 정지시킬 수 있습니다.

고칠 것: 신고 종류별로 원래 글·댓글을 서버에서 조회해 채운다(루틴 신고에 이미 있는 방식 그대로).

2

작성자 이름·운동 기록 카드를 데이터베이스가 정하기

글·댓글 저장 규칙이 사용자 id 만 확인합니다. 앱을 거치지 않고 데이터베이스에 직접 쓰면 이름을 “관리자”로 하거나 하지도 않은 “운동 완료” 카드를 붙일 수 있고, 글 수정으로 내가 속하지 않은 그룹으로 옮길 수도 있습니다.

고칠 것: 저장할 때 이름은 프로필에서, 운동 카드는 서버 동작으로만 넣도록 트리거 추가. 수정은 글 내용만 바꾸게 제한.

운동 영상 좋아요·댓글에 공개 범위 적용

운동 영상의 좋아요·댓글 읽기 규칙이 “누구나”(using (true))라, 그룹 전용 영상의 댓글도 그룹 밖 사람이 읽고 쓸 수 있습니다. 피드 글은 이미 공개 범위를 확인합니다.

4

루틴 신고가 저장되게

신고 표의 허용 종류가 글·댓글·영상·영상 댓글 네 가지뿐이라, 앱이 보내는 “루틴” 신고는 데이터베이스가 거절합니다. 사용자는 신고했는데 관리자에게는 안 옵니다. 저장소 스키마는 라이브 DB와 동기화 검사를 통과하고 있어 라이브도 같은 상태일 가능성이 큽니다.
