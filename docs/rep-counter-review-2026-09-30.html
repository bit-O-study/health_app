짐꾼 운동 횟수 자동 세기

다른 앱들이 운동 반복 횟수를 어떻게 자동으로 세는지 조사하고, 우리 앱에 넣을 방법을 정리했습니다. 결론은 폰 카메라로 몸의 관절 각도를 보고 세는 방식이고, 먼저 스쿼트와 푸시업부터 만드는 것입니다. 필요한 도구(MediaPipe)와 카메라 권한이 이미 앱에 있어 약 1~1.5주면 됩니다. 코드는 바꾸지 않았습니다.

카메라 방식이 세는 원리

  1. 영상의 매 장면에서 어깨·엉덩이·무릎·발목 같은 관절 위치를 찾습니다. 폰 안에서 처리하고 영상은 서버로 보내지 않습니다.
  2. 관절 각도를 계산합니다. 스쿼트는 엉덩이-무릎-발목, 푸시업은 어깨-팔꿈치-손목 각도입니다.
  3. 장면마다 흔들리는 값을 부드럽게 다듬습니다(지수이동평균).
  4. 각도가 90° 아래로 내려가면 "내려감", 다시 160° 위로 올라오면 "올라옴"으로 봅니다. 내려갔다 올라오면 1회입니다.
  5. 내려가는 기준과 올라오는 기준을 다르게 둡니다. 그래서 중간에 몸이 흔들려도 두 번 세지 않습니다.

그림은 원리를 보여 주는 예시입니다. 기준 각도는 운동마다 다르고, 실기기에서 조정합니다. 구글은 여기서 더 나아가 관절 사이 거리를 특징값으로 써서 "앉은 자세일 확률"을 구하는 방식(k-NN)도 씁니다.

추천안

방식

폰 카메라 + 관절 각도

폰 안에서 MediaPipe 몸 인식(가벼운 모델)을 돌리고 관절 각도로 셉니다. 사용자가 원할 때만 켜는 기능으로 둡니다.

세는 규칙(각도 계산, 부드럽게 다듬기, 내려감·올라옴 판정, 운동별 기준)은 화면과 떼어 순수 모듈 rep-counter.ts로 만들어 테스트합니다.

범위

스쿼트 · 푸시업부터

맨몸 운동이라 폰을 옆에 세워 두기 쉽고, 각도 변화가 커서 정확합니다.

스쿼트는 무릎 각도, 푸시업은 팔꿈치 각도를 옆에서 봅니다. 잘 되면 크런치·점핑잭을 더합니다.

흐름

운동 모드에서 "카메라로 세기"

따로 화면을 만들지 않고 지금 쓰는 운동 모드 안에 둡니다.

① "카메라로 세기"를 누르면 "몸 전체가 보이게 옆에 세워 주세요" 안내 → ② 몸이 다 보이면 시작 → ③ 1회마다 음성으로 숫자 → ④ 세트가 끝나면 센 횟수가 반복 칸에 자동으로 들어가고, 사용자가 확인하고 고칠 수 있습니다.

제외

머신·바벨 운동, 워치 연동

헬스장에서는 폰을 세워 두기 어렵고, 주머니 속 폰이나 워치 방식은 이런 운동에서 자주 틀립니다.

워치 기록 표준(Health Connect)에 반복 횟수 칸은 있지만, 삼성 헬스가 근력 운동을 거기로 넘기지 않는다는 보고가 있고 무게 정보도 없습니다.

위험 요소

성능 저사양 폰

느려지고 열이 날 수 있습니다. 그래픽 가속이 안 되면 더 느려집니다. 너무 느리면 "이 폰에서는 정확하지 않을 수 있어요"라고 안내합니다.

로딩 모델 파일 5~9MB

처음 한 번 받아야 하고, 인터넷이 없으면 안 됩니다. 앱에 모델을 같이 넣는 방법을 검토합니다.

정확도 옆에서 찍어야 함

정면이나 비스듬하면 정확도가 떨어집니다. 시작 전에 위치 안내를 보여 줍니다.

규칙 덜 내려간 동작

절반만 앉은 스쿼트를 셀지 정해야 합니다. 추천은 "안 셈"입니다. 그림의 130° 동작처럼 기준까지 내려가야 셉니다.

안정성 메모리

인식 도구를 해제하지 않으면 앱이 튕길 수 있습니다. 런닝 게임처럼 화면을 떠날 때 반드시 해제합니다.

테스트 실제 카메라

자동 테스트로는 실제 카메라를 확인할 수 없습니다. 규칙은 데이터로 테스트하고, 실제 동작은 실기기로 확인합니다.

추천: 무료. 폰 안에서 처리해 비용이 0원이고, 사용자를 모으는 기능입니다.

추천: 안 셈. 기준 각도까지 내려가야 1회로 셉니다.
