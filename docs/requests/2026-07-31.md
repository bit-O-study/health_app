- **(2) `auth.getUser()` → `auth.getClaims()` 전환 (TTFB 직접 개선)**
  - 문제: `getUser()` 는 **문서 요청마다** Supabase Auth 로 HTTP 왕복을 한다
    (icn1 서울 → ap-southeast-1 싱가포르, 왕복 70~90ms). 미들웨어에서 1회,
    페이지 렌더에서 또 1회 — 둘은 실행 컨텍스트가 달라 `React.cache` 로 안 합쳐진다.
    이 왕복은 Next 가 렌더를 시작하기도 전에 TTFB 에 그대로 얹힌다.
  - 확인: 이 프로젝트 JWKS 에 **ES256 비대칭 서명키가 있다** → 로컬 검증이 실제로 된다.
    (대칭키였으면 `getClaims()` 가 원격 폴백이라 효과 0 이었음 — 그래서 먼저 확인함.)
  - 적용: `src/lib/supabase/jwks.ts` 신규 — 공개키 **모듈 스코프 캐시**.
    supabase 클라이언트는 요청마다 새로 만들어져 자체 JWKS 캐시가 매번 비므로,
    모듈 캐시에서 `getClaims(undefined, { keys })` 로 직접 넘긴다 →
    **워밍된 인스턴스에서 인증 네트워크 왕복 0회.**
    `getCurrentUser`(server.ts)·미들웨어 둘 다 전환.
  - 보안: 서명 검증 + `exp` 검사를 거치므로 `getUser()` 와 같은 수준(쿠키를 그냥 믿는
    `getSession()` 과 다름). ⚠ 로그아웃/세션 폐기는 access 토큰 만료(기본 1시간)까지
