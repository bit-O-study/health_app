  ### 원인 3가지 (전부 확인함)
  1. **함수 리전이 계속 icn1(서울)이었다.** `x-vercel-id: icn1::icn1::…` 로 확인.
     7/22 커밋 `a454997` 이 루트 레이아웃에 `preferredRegion = "sin1"` 을 넣었지만
     **Vercel 문서상 `preferredRegion` 은 `runtime='edge'` 일 때만 적용된다** — 이 앱은
     Node 런타임이라 **아무 효과가 없었다.** 게다가 `vercel.json` 에 `"regions": ["icn1"]`
     이 그대로 있어서(5/28 `f38e3e9`) 실제 배포는 계속 서울에서 돌았다.
     Supabase 는 ap-southeast-1(싱가포르) → **모든 쿼리가 70~90ms 왕복.**
  2. **/home 만 스트리밍을 안 했다.** `/routine`·`/calendar`·`/diet`·`/community`·`/groups`
     엔 `loading.tsx` 가 있는데 **/home 에는 없었다.** 그래서 TTFB 가 "모든 DB 조회가
     끝날 때까지" 통째로 밀렸다(= 680ms). /routine 은 셸을 먼저 흘려보내 220ms.
  3. **직렬 왕복 3파.** 프로필을 먼저 받고(1파) → 대시보드 묶음(2파) → 그 안에서
     `getDayDetail` 이 또 2파. 원거리 리전이라 파 하나가 곧 70~90ms.
     덤으로 한 화면에서 `profiles` 를 **세 번**(미들웨어·페이지·`getMyCommitments`) 긁었다.

  ### 적용

    `preferredRegion` 은 제거하고 "왜 안 먹었는지"를 주석으로 남김.
    ↩ 되돌리려면 `vercel.json` 한 줄만 고치면 된다.
  - `src/app/home/loading.tsx` 신규 — 다른 탭과 같은 `RouteLoading`. 셸이 즉시 나간다.
  - 비로그인 `/home` 은 **미들웨어에서 307**(`PROTECTED_PREFIXES` 에 `/home` 추가).
    스트리밍 후엔 페이지 안 `redirect()` 가 소프트 리다이렉트가 되어 느려지기 때문.
    순수부 `isProtectedPath()` 를 `features/auth/protected-paths.ts` 로 분리.
  - `getHomeDashboard()` — 프로필 인자 제거, **전부 한 묶음(Promise.all)** 으로 동시 발사.
    잔디 조회창을 가입일과 무관하게 53주 고정으로 바꿔 프로필 의존을 끊었다
    (표시 주 수만 나중에 가입일로 줄임 — 결과 동일).
  - `getDayDetail()` **2파 → 1파** (식단·걸음수·완료기록·세션을 한 번에). 캘린더도 같이 빨라짐.

    요청 캐시된 `getUserProfile()` 재사용(같은 화면에서 profiles 3회 → 1회).
  - 쓰이지도 않던 `missionCards`/`totalMissions` 계산 제거(페이지가 `[]`·`0` 을 넘기고 있었음).
  - → **/home 페이지 직렬 왕복 3파 → 2파, 쿼리 3개 감소.** TTFB 는 스트리밍으로 셸부터.
