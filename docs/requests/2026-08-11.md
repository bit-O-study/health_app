- **(1) 런닝이 2개일 때 "완료 취소"가 안 된다** — 고침(확인 필요)
  - 사용자 확인 증상: **런닝 2개가 완료돼 있는데, 하나만 취소하면 둘 다 취소된다.**
  - **원인**: 런닝 행의 완료취소만 `removeTodayRunAction()`(인자 없음)이라는 특수 경로를 탔는데,
    이게 *오늘 `item_id='running'` 인 완료기록 **전부***를 지웠다. 게다가
    `daily_conditioning` 의 런닝 **플랜 행까지 전부 삭제**해서, '오늘만'으로 담아둔
    런닝이 사라지거나(그 종류가 비면) 목록이 루틴 기본값으로 되돌아갔다.
    오늘 운동 시간도 **모든 런닝 기록 시간의 합**을 빼서 과다 차감됐다.
  - **고침** (행 단위로):
    - `removeTodayRunAction(sourceRowId)` — **그 행에 배정된 완료기록 1건만** 삭제,
      **그 기록의 시간만** 차감. `daily_conditioning`(플랜 행)은 **더 이상 안 건드린다**.
    - 화면이 행마다 `completionRowId`(그 행을 완료로 만든 기록의 `source_row_id`)를 함께
      내려보낸다 — 런닝모드 기록처럼 행 id 가 아닌 기록이 (종류:항목) 키로 배정된 경우에도
      정확히 그 기록만 지운다. (행 id 로 지우면 0건 삭제 → "취소가 안 먹는" 상태가 됐다.)
    - 취소 쓰기를 다른 완료/취소와 **같은 직렬 큐**(`enqueueWrite`)로 넣어, 옆 행 완료 쓰기와
      겹쳐 서로를 지우던 경합 제거.

- **(2) 팅김(크래시) 증가** — 원인 진단 + 1차 완화(확인 필요)
  - **왜 다시 늘었나**: 팅김 수정은 `8a13c89`(**7/06**)였는데, 그 **뒤 7/13 에 3D 런닝이 크게
    무거워졌다** — 다중 맵 전환(`fd1e335`), **실내 런닝을 힐링 3D 씬으로 통일**(`c87fe0e`,
    이제 실내도 three.js + 카메라 + MediaPipe 를 **동시에** 돌린다), 백그라운드 런닝(`c5528e1`).
    즉 예전 수정은 '더 가벼운 씬' 기준이었고, 지금은 부하가 그때보다 훨씬 크다.
  - **가장 큰 범인**: `visionLoop` 이 **매 프레임(60Hz)** MediaPipe 얼굴 추론을 돌렸다.
    그림자 켠 3D 씬과 GPU 를 초당 60번 나눠 쓰면 중저가 폰은 발열·메모리로 죽는다.
  - **1차 완화(적용)**:
    - 얼굴 감지 **60Hz → 20Hz** (`DETECT_INTERVAL_MS`). 보간은 매 프레임 그대로라 움직임은 동일하게 부드럽다.
    - 씬 `dpr` 상한 **2 → 1.5** (3배 밀도 폰에서 렌더 픽셀 ~1.8배 감소).
    - 그림자 맵 **1024² → 512²** (텍스처 메모리 1/4).
  - 파일: `src/features/running/running-game.tsx`, `src/features/running/zen-scene.tsx`
  - ⚠ **APK 재빌드 필요** — 마지막 릴리스가 `releases/apk/2026-07-28` 이라 이 수정은 아직 폰에 없다.
  - 🔜 더 줄여야 하면: 그림자 아예 끄기(저사양 판정 시), 맵 전환을 `useFrame` 밖으로,
    실내에서 카메라 해상도 640×480 → 320×240.
