## 🔎 진단 (1) — 탭 이동 중 팅김

### A. 네이티브(자바) 크래시는 아닐 가능성이 높다
- 탭 이동(Next `<Link>` = SPA 전환) 중에 **네이티브를 부르는 코드가 하나도 없다.**
  - `window.HelssuNative` 호출부는 `src/features/running/native.ts` 뿐(런닝 전용).
  - Health Connect(`getStepsState`)·FCM(`registerNativePush`) 자동호출은 `03397af` 에서 이미 제거,
    지금은 **사용자가 버튼을 눌러야만** 불린다(`permission-nudge.tsx`, `steps-sync.tsx`).
- 설치된 APK(`releases/apk/2026-08-20/helssu-debug-v3-login-fix.apk`)의 dex 를 열어 확인:
  `onRenderProcessGone`·`HelssuNative`·`scheduleReload`·`loadOAuthCallback` **전부 들어 있음**
  → 네이티브 수정은 폰에 반영된 게 맞다. (v2 와 크기는 같지만 md5 는 다름 = 다른 빌드)

### B. 진짜 원인 — WebView **렌더러 프로세스**가 메모리로 죽는다
이 앱은 리모트 URL 을 WebView 하나에 띄우는 SPA다. 탭을 옮겨도 **문서가 안 바뀌므로**
방문한 탭의 JS·RSC 페이로드·이미지가 **한 렌더러 프로세스에 계속 쌓인다.**
쌓이는 양이 실제로 크다:

| 항목 | 크기 |
|---|---|
| `.next/static/chunks` 전체 | 약 6.0 MB (최대 단일 청크 943 KB) |
| `src/features/routine/exercise-catalog-extra.ts` | **727 KB** (클라 컴포넌트에서 import) |
| `exercise-catalog.ts` / `exercise-guides.ts` | 88 KB / 85 KB |
| `food-catalog-world.ts` + `food-catalog.ts` | 123 KB |
| `exercise-icon.tsx` (인라인 SVG) | 59 KB |
| `public/exercise-guides/*.mp4` | **124 MB** (scapula 46.5MB, squat 35.6MB, bench 25.1MB) |

`largeHeap="true"` 는 **앱 프로세스에만** 적용되고 WebView 렌더러엔 효과가 없다.
안드로이드는 앱 소속 렌더러를 우선적으로 회수하므로 중저가폰에선 쉽게 죽는다.

### C. 그래서 왜 "팅긴 것처럼" 보이나 — 회복 코드 두 개가 충돌한다 🔴
1. `MainActivity.onRenderProcessGone` (`f0667ba`) 는 렌더러가 죽으면 `recreate()` 한다.
   주석에도 적혀 있듯 **"죽은 그 페이지가 아니라 시작 URL 로"** 복구해야 crash loop 를 막는다.
2. 그런데 `src/app/_route-keeper.tsx`(`RouteKeeper`, 7/13) 가 부팅 직후
   **/ 또는 /routine 이면 30분 내 마지막 경로로 `router.replace()`** 해버린다
   (`src/lib/platform/route-restore.ts:HOME_PATHS`).

→ 결과: 렌더러를 터뜨린 화면(예 `/diet`)으로 **자동으로 다시 들어간다 → 또 죽는다 → 또 복원**.
   MainActivity 가 의도한 crash-loop 방지가 **RouteKeeper 때문에 무효화**된다.
   사용자 눈엔 "탭 돌아다니다 보면 화면이 번쩍이며 앱이 튕긴다"로 보인다.

### D. 최종 확인 방법(실기기 필요)
폰 USB 디버깅 켜고 연결한 뒤:
```
adb logcat -c
adb logcat | grep -Ei "helssu|WebViewRender|chromium|FATAL|lowmemorykiller|am_kill|DEAD_OBJECT"
```
- `Render process (pid …) kill(true)` / `WebViewRenderProcessGone` → B 확정(렌더러 OOM).
- `FATAL EXCEPTION` 스택 → 네이티브 크래시(=A 뒤집힘).

### E. 고칠 때 후보(아직 안 함 — 사용자 결정 대기)
1. **RouteKeeper 를 렌더러 사망 복구와 분리** — 네이티브가 "크래시 복구 부팅"임을 알려주고
   그 부팅에서는 복원하지 않기(가장 직접적, 루프 즉시 차단).
2. 렌더러 사망이 반복되면(예: 3분 내 2회) 복원 완전 차단 + 안내.
3. 메모리 줄이기: `exercise-catalog-extra` 를 클라 번들에서 빼고 서버/동적 로드,
   운동 가이드 mp4(25~46MB)를 스트리밍/압축본으로 교체, 탭 프리페치 축소.
