### 개인정보 — 원문을 저장하지 않는다
이메일·uuid·토큰·긴 숫자·쿼리스트링을 **자리표시자로 치환**한다(지우는 게 아니라
바꾼다 — 무슨 종류였는지는 남아야 같은 오류끼리 묶인다). 경로의 가변 조각도
`/groups/:id`·`/calendar/:date` 로 묶는다. 관리자 화면 하단에 "무엇을 수집하지 않는지"를
명시했다 — 관측이 사찰이 되면 안 된다.

### 입구를 닫았다
크론 기록에서 "인증 실패는 기록하지 않는다(아무나 행을 쌓으면 그게 구멍)" 고 정한 것과
같은 이유로, **로그인한 사용자의 것만 그 사람 user_id 로만** 들어간다.
- RLS `auth.uid() = user_id`(insert) / 읽기는 관리자 + 본인
- 사용자당 시간당 200행, 한 요청당 30개 상한
- E2E 가 **DB 권한으로 직접** 남의 user_id 삽입을 시도해 막히는지 확인한다

### 작업 중 발견해서 고친 것
- **메시지 세분화가 합산을 무력화**했다. `첫 로딩 6332ms` 처럼 밀리초를 넣으면
  문자열이 매번 달라 "같은 사건" 판정이 절대 안 걸린다 → 초·100MB 단위로 뭉개고
  정확한 값은 `value` 에. (E2E 로 화면을 도는 것만으로 행이 쌓이는 걸 보고 찾았다)
- **서버 액션을 정적으로 import 하면** 이 모듈을 쓰는 화면 전부(걸음수 브리지·로그인
  폼·운동모드)의 그래프에 서버 모듈이 얹혀, 순수 단위 테스트까지 supabase 환경변수를
