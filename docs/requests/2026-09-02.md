## 🛠 작업 (1) — 2.2 과부하 추천을 '무게를 정하는 자리'에 노출

어제 2.2 를 만들면서 남겨 둔 항목. 추천이 **성장 그래프에만** 있어서, 정작 무게를
정하는 운동모드·계획 편집에서는 안 보였다. 그때 막혔던 이유(해당 화면을 다른 세션이
잡고 있었다)가 풀려서 이어서 했다.

### 한 것

| 파일 | 역할 |
|---|---|
| `overload-advice.ts` (신규) | 판단 → **화면값**. 말머리·강조 여부·직렬화 가능한 모양 |
| `components/overload-hint.tsx` (신규) | 표시 한 줄 — 세 화면이 **같은 모양**으로 쓴다 |
| `overload-actions.ts` (신규) | 계획 편집이 필요할 때만 받아가는 서버 액션 |
| `today-exercises.tsx` | 운동모드 큐(`GuidedItem`)에 추천을 실어 보낸다 |
| `guided-workout.tsx` | 무게 스크러버 **바로 아래** 표시 + '적용' |
| `plan-editor.tsx` | 운동 줄 아래 표시 + '적용'(무게·횟수 입력란 채움) |
| `settings/progress/page.tsx` | 자기 화면에만 있던 표시 코드를 공용 컴포넌트로 교체 |

### 🔴 왕복을 안 늘렸다 — 조회를 합쳤다
추천의 근거(최근 완료 기록)는 미리채움(`getLastExerciseValues`)이 **이미 읽고 있던 것과
같은 표·같은 조건**이었다. 따로 읽으면 서울↔싱가포르 왕복이 한 번 더 는다 →
`getRecentDoneRecords`(요청 단위 `cache()`) 하나로 합치고 미리채움이 그걸 가공하게 했다.
겸사겸사 **`set_details` 를 같이 읽는다** — 드롭세트가 거기 있어서, 빼면 추천이 균일
세트로만 계산돼 1RM 이 틀어진다(2.1 에서 겪은 결함).

### 🔴 하마터면 넣을 뻔한 함정 — 스스로를 만족시키는 목표
비고정 모드의 오늘 계획값은 **지난번 실제 횟수로 미리 채워져 있다.** 그걸 목표 횟수로
넘기면 "지난번 = 목표" 가 되어 **매번 '목표 달성 → 증량'** 이 걸린다. 그래서 목표는
**미리채움 전(`orderedPlan`)** 값으로 본다(고정 모드) / 없으면 처방 기준.
`AdviceTarget.targetReps` 주석에 못 박고 단위 테스트로 고정했다.

### '적용' 을 다는 규칙
읽고 손으로 옮겨 적게 두면 쓸모가 반이라 버튼을 달되, **누를 때만** 값이 바뀐다
(제안이 값을 몰래 바꾸면 그건 추천이 아니다). 안 다는 자리 셋:
- **휴식 권장** — 넣을 값 자체가 없다(눌러도 아무 일이 없는 버튼을 만들지 않는다)
- **고정 모드 운동모드** — 거기엔 스크러버가 없다(무게를 바꿀 수 없다). 근거만 읽기 전용
- **세트별 기록(드롭세트) 줄** — 균일 무게 칸이 없어 넣을 곳이 없다

### 계획 편집은 왜 서버 액션인가
첫 렌더에 다 실으면 ① 편집 중 **바꾼 운동**은 추천이 없고 ② `/plan` 초기 응답만 무거워진다.
목록이 바뀔 때만 다시 물어본다 — 횟수를 한 글자 고칠 때마다 서버를 부르면 편집이 끊긴다.
무게 칸이 없는 비고정 모드에서는 **아예 안 부른다**(넣을 곳이 없는 제안은 소음이다).

끊기는 시점은 매번 다르다 — DB 쓰기 **전에** 끊긴 경우(기록이 아예 안 남음)와
**후에** 끊긴 경우(기록은 남고 화면만 안 바뀜)를 둘 다 관측했다.

**세운 가설과 결과**
