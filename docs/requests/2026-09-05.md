## B. 🟠 코드로 지금 할 수 있는 것 (제가 할 수 있는 일)

우선순위 순. 괄호는 예상 작업량.

### B-1. 보안 헤더가 하나도 없다 (작음, 반나절)
`next.config.ts`·`middleware.ts` 어디에도 CSP·X-Frame-Options·Referrer-Policy·
Permissions-Policy·HSTS 가 없다(grep 0건). `poweredByHeader:false` 만 있다.
- **왜 지금**: 이 앱은 카메라(자세·식단·기구 스캔)·위치(러닝)·알림 권한을 쓴다.
  `Permissions-Policy` 가 없으면 iframe 에 끼워졌을 때 그 권한이 같이 새어 나간다.
  `X-Frame-Options` 가 없어 **클릭재킹으로 계정 삭제·구독 버튼을 누르게 만들 수 있다.**
- CSP 는 Next 인라인 스크립트 때문에 nonce 를 붙여야 해서 한 번에 조이지 말고
  `Report-Only` 로 먼저 깔고 위반을 보며 좁히는 게 맞다.

### B-2. 오프라인이면 앱이 빈 화면이다 (중간, 2~3일) ⭐ 가장 값어치 있음
- `navigator.onLine` 사용 **0곳**, 오프라인 UI **0곳**.
- `public/sw.js` 는 캐싱을 **의도적으로 안 한다**(주석에 "필요해지면 그때 추가").
- 앱은 Capacitor **원격 URL 방식** — WebView 가 Vercel 을 그대로 로드한다.
  `native-shell/index.html`(1.3KB)은 폴백이라 적혀 있지만 실제로는 안 쓰인다.
- **헬스장은 지하가 많다.** 지금은 신호가 끊기면 운동모드 한복판에서 화면이 죽고,
  그때까지 친 세트 기록도 서버로 못 간다.
- 최소안: ① SW 에 앱 셸 + 오늘 운동 큐 캐싱 ② 세트 완료를 IndexedDB 큐에 쌓고
  복구되면 동기화 ③ 상단에 "오프라인 — 기록은 저장되고 연결되면 올라갑니다" 배너.
- 이건 **1.1 팅김 이슈와도 겹친다** — 사용자가 "튕겼다"고 느낀 것 중 일부는
  네트워크 끊김일 수 있는데, 지금 구조로는 둘을 구분할 방법이 없다.

### B-3. 운동 시연 사진이 남의 CDN(jsdelivr)에 묶여 있다 (중간)
`exercise-photo-map.ts` — 운동모드에서 보여주는 시연 2프레임을 전부
`jsdelivr` 로 free-exercise-db 에서 받아온다. 코어 화면이 **우리가 통제 못 하는
외부 CDN** 에 걸려 있다. jsdelivr 가 느리거나 막히면 운동모드에 사진이 안 뜬다.
B-2(오프라인)도 이것 때문에 반쪽이 된다. → 쓰는 것만 골라 Supabase Storage 나
`public/` 로 옮기고(퍼블릭도메인이라 라이선스 문제 없음) CDN 은 폴백으로.

### B-4. 404 페이지가 없다 (아주 작음, 1시간)
`src/app/not-found.tsx` 부재 → 잘못된 주소는 **Next 기본 영어 화면**
("This page could not be found")이 뜬다. 한국어 앱에서 갑자기 영어 흰 화면이 나오면
사용자는 앱이 고장 났다고 읽는다. `error.tsx` 는 있는데 `not-found` 만 빠졌다.

### B-5. 레이트 리밋이 어디에도 없다 (작음~중간)
grep 0건. 지금 문제 되는 자리 셋:

   가입 이메일이 그대로 나온다. 시도 횟수 제한이 없어 **대입으로 긁을 수 있다.**
   9/4 문서에도 "나중에 조이려면 마스킹이나 횟수 제한" 이라고 남겨 뒀다.
2. **AI 호출 7곳** — 월 한도(`ai_usage`)는 있지만 **분당 폭주 방지가 없다.**
   NVIDIA 무료 티어가 분당 40요청이라, 한 사람이 연타하면 한도를 다 쓰기 전에

3. **로그인** — 비밀번호 대입 제한 없음(Supabase 기본에만 의존).

### B-6. 미참조 정적 자산 19.7MB (아주 작음 — 다만 삭제는 사용자 확인 필요)
