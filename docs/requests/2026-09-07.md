처음엔 "활용신청해야 주소를 알 수 있다" 로 넘겼는데, 사용자 질문("키 주소는 어떤 거 넣어야
되는데?")을 받고 끝까지 파서 **주소·파라미터·응답 필드를 전부 확정**했다.
data.go.kr 상세 페이지의 요청변수 정의를 읽고, **빈 키로 실제 호출**해 서비스 존재를 확인
(`SERVICE_KEY_IS_NOT_REGISTERED_ERROR` = 서비스는 있고 키만 없다는 뜻).

1. [www.data.go.kr](https://www.data.go.kr) → **'전국통합식품영양성분정보(음식)'** 검색 →
   **활용신청**(자동 승인)
2. 마이페이지 > 오픈API > **일반 인증키(Decoding)** 복사
3. `.env.local` 과 **Vercel 환경변수**에:

```
FOOD_DB_URL=https://api.data.go.kr/openapi/tn_pubr_public_nutri_food_info_api?serviceKey={key}&pageNo=1&numOfRows={rows}&type=json&foodNm={query}
FOOD_DB_API_KEY=발급받은_Decoding_키
```

**`FOOD_DB_URL` 은 위 줄을 그대로** 쓰시면 됩니다. 바꿀 건 키뿐입니다.

> ⚠ 인증키는 **Decoding 값**을 넣으세요. Encoding 값(`%2B`·`%3D` 섞인 것)을 넣으면
> 코드가 한 번 더 인코딩해서 `SERVICE_KEY_IS_NOT_REGISTERED_ERROR` 가 납니다.

원재료성 식품(쌀·달걀 등)까지 보려면 주소만 `tn_pubr_public_nutri_material_info_api` 로
바꾸면 됩니다(파라미터 동일).

| 응답 봉투 | `{ response: { header: {resultCode}, body: { items: [...] } } }` — `resultCode '00'` 만 정상 |
| 필드 | `foodNm` · `nutConSrtrQua`(기준량) · `enerc`(kcal) · `prot` · **`fatce`**(지방) · `chocdf`(탄수) |

🔴 **지방은 `fatce`** 다. `fasat`(포화)·`fatrn`(트랜스)을 집으면 값이 통째로 틀리는데
화면은 멀쩡해 보인다 — 테스트로 못 박았다.

주소는 그래도 **환경변수 템플릿**으로 받는다. 이 계열 API 는 통째로 갈린다(아래 표) —
박아 두면 다음에 갈릴 때 화면엔 '검색 결과 없음' 만 조용히 뜬다.

**찾은 음식은 `custom_foods` 에 쌓는다**(`source='food-db'`). 다음부터는 우리 DB 에서
바로 나오므로 공공 API 를 다시 안 부르고, 그 API 가 죽어도 그 음식은 계속 검색된다.
이미 등록된 이름은 **덮지 않는다** — 사용자가 고쳐 둔 값을 공공 데이터가 되돌리면
고장으로 읽힌다.

### 조심한 것들

- 🔴 **인증 실패·서비스 폐기도 HTTP 200 이다**(두 포털 다). 본문 코드를 보고 '결과 없음'과
  구분해 서버 로그에 남긴다. 안 그러면 연동이 끊겨도 화면상 똑같아 몇 달을 모른다.
- ⚠ **기준량은 문자열**이다(`"100g"`·`"1접시(250g)"`). 숫자로 읽으면 0 이 되고 그 순간
  모든 음식이 "1회 제공량" 으로 뭉개진다.
- 전부 0 인 행은 버린다(0kcal 음식으로 기록되면 안 된다). 제조사·조사연도별 중복은 접는다.
- **사용자당 분당 20회** 제한(작업 (1) ③ 의 폭주 제한 재사용) — 우리 비용은 아니지만
  키 하나를 모두가 나눠 쓰고 일일 한도가 있어, 한 사람의 재시도가 그날 남은 조회를 태운다.
- 실패는 조용히 넘긴다. **보조 출처**라 여기서 던지면 멀쩡한 검색까지 죽는다.
