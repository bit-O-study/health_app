## 🛠 작업 (1) — 식단 화면에 남아 있던 왕복 두 개

9/8 작업으로 **서버 안쪽**(SQL·리전)은 정리됐다. 남은 지연은 전부
**브라우저 → 싱가포르(sin1) hop(~80ms)** 쪽이었다. 그 hop 을 두 군데서 줄였다.

### ① 식약처 실시간 조회 — 매 검색 → **빈손일 때만**

검색창은 출처가 셋이다(정적 카탈로그 · `custom_foods` · 식약처 실시간).
예전엔 **검색어마다 셋을 나란히** 불렀다.

🔴 그런데 식약처 API 는 `foodNm` 이 **완전일치**다(9/7 실측: '김치'·'밥'·'닭가슴살'
전부 NODATA). 사용자가 치는 말에는 거의 항상 0건이다 — 즉 대부분의 검색이
**결과가 나오지도 않는 외부 왕복**을 한 번씩 더 태우고 있었다. 화면은 이미 정적·custom
결과로 채워진 채로.

그래서 **앞의 두 출처가 빈손일 때만** 부르게 했다.

- 이 출처가 값을 하는 자리는 "우리 둘 다 모르는 음식"(편의점 도시락·가공식품)이고,
  그건 앞의 둘이 **빈손일 때 정확히 알 수 있다.**
- **AI 한도를 아끼는 원래 목적은 그대로다** — 찾으면 `custom_foods` 에 쌓이고
  다음부터는 우리 DB 에서 나온다.
- 평소 검색에서는 요청이 **아예 사라진다**(3개 → 2개).

`useFoodSearch` 에 `enabled` 스위치를 더했다. 잠긴 동안엔 요청도 안 나가고
`loading` 도 false 다 — true 로 두면 켜지지 않는 출처 때문에 스피너가 영원히 돈다.

### ② 식단 날짜 이동(← →) — 누른 뒤 왕복 → **미리 받아 둠**

`<button onClick={router.push}>` 이었다. 누른 **다음에야** 서버 렌더가 시작되니
한국↔싱가포르 왕복이 그대로 기다리는 시간이었다.

→ **`<Link prefetch>`** 로 바꿨다. 화면에 보이는 순간 어제/내일을 미리 받아 둔다.

🔴 **`prefetch` 를 빠뜨리면 아무 소용이 없다.** 동적 라우트는 기본이
`staleTimes.dynamic = 0초` 라 받아 두자마자 낡은 것으로 처리된다.
`prefetch`(=true)여야 `staleTimes.static`(기본 5분)이 적용돼 실제로 재사용된다.
(저장·삭제 뒤 `router.refresh()` 가 이 캐시도 같이 무효화하므로 낡은 값이 남지 않는다.)

- 오늘이면 '다음 날'은 주소가 없으니 그대로 비활성 버튼.
- 저장 중(`pending`)에는 옛 `disabled` 와 똑같이 막는다(낙관적 상태 보호).
- ⚠ 대가: 식단을 열 때마다 **어제 페이지가 한 번 더 서버 렌더**된다(과거 날짜면 2개).
  쿼리 4개 × ~5ms 짜리라 감당되는 값이라고 봤다.
