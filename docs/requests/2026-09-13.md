## 🛠 작업 A — 러닝 렌더 중 ref 쓰기 제거 (9/5 조사 B-8)

**9/5 조사의 진단은 절반만 맞았다.** "린트 기준선 11건이 팅김 주범 파일에 몰려 있다"는
사실이지만, `zen-scene.tsx` 의 6건은 **고칠 자리가 아니다** — `scene.background = tex`,
`action.timeScale = …` 는 three.js/r3f 의 유일한 API 이고, HUD 는 60fps 로 리렌더하지
않으려고 일부러 DOM 을 직접 쓴다. 린트가 그 객체를 React 상태로 오해할 뿐이다.
파일 머리에 **"여기는 손대지 말 것 + 실제 누수는 이미 고쳐진 세 곳"** 을 적어 뒀다
(다음 사람이 기준선을 지우겠다고 해제 경로를 깨지 않도록).

**진짜 버그였던 건 두 곳.**

- 🔴 `running-game.tsx` — `phaseRef.current = phase` 를 **렌더 중에** 대입하고 있었다.
  이 ref 는 `visionLoop` 가 매 프레임 읽어 **다음 RAF 를 예약할지 말지**를 정한다
  (`phaseRef.current !== "done"`). 렌더 중 대입은 **버려지는 렌더**(동시성 렌더 중단·
  StrictMode 이중 호출)의 phase 를 ref 에 남길 수 있고, 그러면 멈춰야 할 루프가 안 멈춰
  **RAF 가 카메라·MediaPipe WASM 을 계속 붙잡는다** — 메모에 적힌 팅김 누수와 같은 계열.
  `useEffect(..., [phase])` 로 옮겨 **커밋된 화면과 항상 일치**하게 했다.
- `run-leaderboard.tsx` — `sessionRef.current = getSessionMeters` 도 같은 계열.
  이 ref 는 1초 인터벌(커밋 이후에만 도는 코드)에서만 읽으므로 effect 로 충분하다.
- `visionLoop` 선언을 `resumeCamera` 위로 올렸다(호이스팅 의존 제거). 순수 이동.

**검증이자 회귀 방어**: 이 변화는 화면에 새 동작을 만들지 않으므로 새 단언을 쓸 자리가
없다. 대신 **린트 기준선을 20 → 16 으로 낮췄다** — 누가 다시 렌더 중에 ref 를 쓰면
`pnpm lint:gate` 가 CI 에서 떨어진다. 기존 러닝 E2E 15개·단위 1,894개 통과, `tsc` exit 0.

## 🛠 작업 B — 오프라인 운동 기록 (9/5 조사 B-2 / D-1)

**무엇이 깨져 있었나.** 헬스장 지하에서 세트를 치면 서버 액션이 실패하고, 그 기록은
**운동모드 화면의 메모리(`failedSavesRef`)에만** 남았다. 화면을 벗어나거나 앱이 죽으면
그대로 증발한다. 사용자는 분명 완료를 눌렀는데 다음 날 기록이 비어 있다.
게다가 빨간 "저장 실패 — 다시 시도" 배너가 떠서, 연결이 돌아올 때까지 **할 수 없는 일을
하라고** 시키고 있었다.

**고친 구조** — `src/lib/offline/`

- `pending-writes.ts` (순수) — 담기·빼기·만료·문구. 같은 행을 다시 누르면 **덮어쓴다**
  (upsert 라 마지막 것만 올리면 결과가 같다. 쌓으면 왕복만 늘고 중간 상태가 깜빡인다).
- `pending-store.ts` — localStorage. 🔴 **IndexedDB 가 아닌 이유**: 전부 비동기라
  페이지가 닫히는 순간 쓰기를 못 끝낼 수 있는데, 하필 그 순간이 제일 지키고 싶은 순간이다.
  읽기·쓰기를 전부 try/catch — 시크릿 모드·용량 초과에서 localStorage 는 **접근만 해도
  던진다.** 기록을 지키려던 코드가 운동모드를 죽이면 안 된다.
- `pending-queue.ts` — 큐는 **화면 밖**에 둔다. 담는 건 운동모드지만 올릴 수 있게 되는
  순간은 어느 화면에서든 온다. 한 번에 하나씩 순서대로 보낸다(지하에서 막 나온 약한
  회선에 동시 요청을 몰면 또 실패한다). 실패하면 거기서 멈추고 **큐에 남긴다.**
- `components/offline-banner.tsx` — 전역. `z-[75]` 로 운동모드 오버레이(z-40)·마무리
  화면(z-70) 위, 모달(z-80) 아래 — 오프라인이 제일 아쉬운 순간이 운동모드 한복판이다.

**🔴 `forDate` 를 큐가 들고 다닌다** (`queued-date.ts`). 서버 액션은 원래 날짜를 서버에서
`seoulYmd()` 로 정하는데, 큐는 **나중에** 올린다 — 23:55 에 친 세트가 00:05 에 올라가면
하루 밀려 주간 분석(작업 A~I 로 방금 만든 그것)이 통째로 어긋난다. 누른 순간의 날짜를
박아 보낸다. 그렇다고 클라이언트 날짜를 그냥 믿으면 **지난달을 채워 넣어** 연속 기록·
랭킹을 만들어 낼 수 있으므로 서버가 **오늘/어제만** 받는다. 벗어나면 거절이 아니라
오늘로 떨어뜨린다 — 악의보다 기기 시계 문제일 가능성이 크고, 거절하면 그 세트는 영영 없다.

**🔴 "실패"와 "대기"를 같은 색으로 칠하지 않는다.** 빨강은 *사용자가 할 일이 있다*,
주황은 *아무것도 안 해도 된다*. 오프라인이면 빨간 배너를 아예 띄우지 않고 큐로 보낸다.
운동 종료 문구도 갈랐다 — 오프라인에서 "다시 시도해 주세요"는 거짓말이다.

**🔴 큐가 비어 있으면 오프라인이어도 아무 말 안 한다.** 잃을 게 없는데 경고만 띄우면
다음에 진짜 필요할 때 아무도 그 자리를 안 본다.

**린트 게이트가 제 코드를 잡았다.** 배너에서 `useEffect` + `setState` 로 온라인 여부를
따라가다 걸렸다. 기준선을 올리지 않고 `useSyncExternalStore` 로 고쳤다 — 첫 프레임이
항상 "온라인·큐 없음"으로 나오던 한 박자 지연도 같이 사라졌다.
