**고친 구조** — `src/lib/offline/`

- `pending-store.ts` — localStorage. 🔴 **IndexedDB 가 아닌 이유**: 전부 비동기라

  던진다.** 기록을 지키려던 코드가 운동모드를 죽이면 안 된다.

  순간은 어느 화면에서든 온다. 한 번에 하나씩 순서대로 보낸다(지하에서 막 나온 약한
  회선에 동시 요청을 몰면 또 실패한다). 실패하면 거기서 멈추고 **큐에 남긴다.**
- `components/offline-banner.tsx` — 전역. `z-[75]` 로 운동모드 오버레이(z-40)·마무리

**🔴 "실패"와 "대기"를 같은 색으로 칠하지 않는다.** 빨강은 *사용자가 할 일이 있다*,

## 🛠 작업 C — service worker 셸 캐싱 (9/5 조사 B-2 ①)

**사용자 요청**: "sw 캐싱도 해줘".

`public/sw.js` 는 "Next 자체 캐시와 충돌하면 디버깅이 어렵다" 며 캐싱을 통째로 비워 둔
상태였다. 그 걱정의 실체는 하나로 좁혀진다 — **방문한 화면의 HTML 을 캐시하는 것.**
이 앱 화면에는 어제의 루틴·완료 기록·체중이 서버 렌더로 박혀 있어서, 그걸 다시 띄우면
사용자는 오늘 값인 줄 안다. **빈 화면보다 나쁘다.**

그래서 **화면 HTML 은 캐시하지 않는 설계**로 갔다. 이러면 "배포했는데 옛 화면이 남는"
사고가 **구조적으로 불가능**하다.

| 무엇 | 어떻게 | 왜 |
|---|---|---|
| `/_next/static/**` | 캐시 우선 | 파일명에 내용해시가 있어 같은 URL 이면 내용이 안 바뀐다. 지하 와이파이의 청크 로드 실패도 같이 줄어든다 |
| 화면 이동(navigate) | **네트워크 우선**, 실패 시에만 `/offline.html` | 화면은 서버가 유일한 출처 |
| POST·API·`/auth/`·RSC·외부 출처 | 손대지 않음 | 서버 액션(완료 저장)이 전부 POST 다. 여기 건드리면 기록이 사라지거나 두 번 저장된다 |

- `public/sw-strategy.js` — 판정만 떼어 낸 순수 파일. 🔴 **왜 뺐나**: service worker 는
  한번 잘못 깔면 사용자 브라우저에 남아 배포해도 바로 안 고쳐지는데, `sw.js` 는
  `addEventListener` 덩어리라 테스트가 못 부른다. 단위테스트가 **배포되는 그 파일을
  그대로** 불러 검증한다(복사본이 아니라).
- `public/offline.html` — 바깥에서 불러오는 CSS·폰트·스크립트가 **하나도 없다.**
  네트워크가 죽었을 때 내놓는 화면인데 외부 의존이 있으면 그것도 같이 실패해 깨진다.
  개인 데이터도 한 글자 없고, 대신 **기기에 남은 대기 건수**를 [작업 B] 의 큐에서 읽어
  "네 세트는 안전하다" 고 알려 준다(같은 localStorage 키).
- 🔴 **정적 캐시 상한 120개.** 배포마다 청크 해시가 바뀌어 옛 항목이 안 지워지고 쌓인다.
  저장공간을 많이 먹으면 브라우저가 이 캐시를 **통째로** 비워 오프라인 안내 화면까지
  날아간다. 상한이 `undefined` 가 되면 `length - undefined = NaN` 이라 정리 루프가
  한 번도 안 돌고 **조용히** 무한히 커지므로, 그 자체를 단위테스트로 막았다.

## 🛠 작업 D — 운동 시연 영상 캐싱

**사용자 요청**: "영상도 캐시해줘".

### 🔴 함정 두 개를 먼저 확인했다

**① Range 요청.** `media-embed.tsx` 의 `<video preload="metadata">` 는 파일 전체가
아니라 앞부분만 달라고 한다(`bytes=0-`). 캐시해 둔 200(전체) 응답을 그 요청에 그대로
돌려주면 브라우저는 "Range 를 요청했는데 전체가 왔다" 로 보고 **탐색이 망가지거나
재생이 멈춘다.** 반대로 206(조각) 응답을 캐시해 두면 다음에 전체를 요청했을 때 잘린
조각이 나간다. → **캐시엔 전체만 담고**(캐시 키에서 Range 를 뗀다), 부분 요청은 SW 가
잘라 206 으로 만들어 준다(`parseRange`).

**② 용량.** 실측 181개 32MB(평균 181KB). 전체 카탈로그 1,351종으로 가면 **~245MB** 다.
그래서 **미리 받지 않고 본 것만** 담는다.

### 정한 값 — 실측에 근거해서

| 값 | 근거 |
|---|---|
| 한 파일 상한 **2MB** | 181개 중 175개가 0.5MB 미만, 1.5MB 초과는 4개뿐. 그 4개를 담겠다고 예산을 쓰면 자주 보는 나머지가 밀려난다. 넘는 건 캐시 안 하고 네트워크로 흘려보낸다(재생은 정상) |
| 전체 예산 **24MB** | 🔴 개수가 아니라 **바이트**로 묶는다. 개수로 묶으면 181KB 짜리와 2MB 짜리가 같은 한 칸을 먹어 실제 저장량을 정할 수 없다. 크기는 **헤더만** 읽어 재므로(본문 안 읽음) 싸다 |
| **별도 캐시 통** (`helssu-media-v1`) | 영상은 정리·퇴출이 잦은데 셸 캐시에 섞으면 그 와중에 `offline.html`(마지막 보루)까지 날아간다 |
| `activate` 에서 **영상 캐시는 안 지운다** | 배포와 무관하게 같은 URL = 같은 파일. 지우면 사용자가 수십 MB 를 다시 받는다 |
