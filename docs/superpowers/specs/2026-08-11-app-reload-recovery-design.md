# 앱 강제 재진입 방지와 오류 복구 설계

## 문제

앱을 사용하다가 특정되지 않은 동작 뒤 스플래시부터 다시 나타나며 초기 화면으로
돌아가는 현상이 있다. 현재 `app/error.tsx`와 `app/global-error.tsx`는 전달받은 오류를
검사하지 않고, 모든 라우트·렌더 오류에서 30초 내 한 번 `window.location.reload()`를
호출한다. 이 전체 새로고침은 루트 레이아웃과 스플래시를 다시 마운트하므로 앱이 튕긴
것처럼 보이며, 최초 오류도 화면에서 사라져 원인 추적을 어렵게 한다.

배포 후 사라진 청크나 일시적인 네트워크 로드 실패는 전체 새로고침으로 복구할 가치가
있다. 따라서 자동 복구 자체를 제거하지 않고, 복구 가능한 로드 오류에만 제한한다.

## 검토한 접근

1. **복구 가능한 로드 오류만 자동 새로고침하고 나머지는 오류 화면에 남긴다. (선택)**
   기존 청크 복구는 유지하면서 일반 코드 오류가 앱 전체를 초기화하는 현상을 막는다.
   오류 정보도 보존해 재현 경로가 일정하지 않은 문제를 추적할 수 있다.
2. 모든 오류의 자동 새로고침을 유지하고 오류 정보만 저장한다. 원인은 추적할 수 있지만
   사용 중 초기 화면으로 돌아가는 현상은 계속된다.
3. 자동 새로고침을 모두 제거한다. 임의 초기화는 막지만 새 배포 뒤 옛 청크를 물고 있는
   설치형 앱이 스스로 복구하지 못한다.

## 설계

### 오류 분류

`chunk-recovery.ts`에 오류 메시지를 보고 전체 새로고침으로 복구 가능한지 판단하는 순수
함수를 둔다.

- 기존 청크·동적 import·CSS 청크 로드 오류는 복구 가능하다.
- `Failed to fetch`, `NetworkError`, `Load failed`, 연결 변경·끊김 등 일시적인 네트워크
  로드 오류는 복구 가능하다.
- `TypeError`, React 렌더 오류, 잘못된 데이터 접근 같은 일반 코드 오류는 복구 대상으로
  보지 않는다.

30초 내 한 번만 새로고침하는 기존 `shouldAutoReload` 가드는 그대로 사용한다.

### 에러 바운더리

`error.tsx`와 `global-error.tsx`가 기존에 무시하던 `error` 값을 실제로 사용한다.

- 복구 가능한 오류이고 최근 자동 새로고침 기록이 없으면 기존처럼 한 번 새로고침한다.
- 일반 코드 오류이거나 방금 이미 새로고침했다면 전체 앱을 다시 띄우지 않는다.
- 대신 현재 오류 화면에서 `다시 시도`를 제공한다. 라우트 에러 화면의 수동
  `새로고침` 버튼은 사용자가 명시적으로 선택하는 기능이므로 유지한다.

`PWARegister`의 전역 청크 오류 감지와 안드로이드 `MainActivity`의 메인 프레임 네트워크
재시도는 이미 복구 가능한 로드 실패에 한정되어 있으므로 변경하지 않는다.

### 진단 정보

에러 바운더리가 받은 오류를 새로고침 전에 잃지 않도록 다음 최소 정보를
`localStorage`의 단일 최신 항목에 저장한다.

- 발생 시각
- 현재 경로명(pathname만 저장하고 query string은 제외)
- 오류 메시지
- Next.js 오류 digest(있는 경우)
- 자동 새로고침 대상으로 분류됐는지 여부

스택과 사용자 입력 데이터는 저장하지 않는다. 최신 한 건만 덮어써 저장량과 개인정보
노출을 제한한다. 경로와 메시지는 각각 500자, digest는 120자로 잘라 저장한다. 저장
실패는 앱 동작에 영향을 주지 않는다.

## 기존 동작과의 관계

- 새 배포 뒤 청크가 없어진 경우: 기존처럼 한 번 자동 새로고침한다.
- 일시적인 메인 화면 네트워크 실패: 안드로이드 네이티브 재시도가 계속 처리한다.
- 일반 렌더 오류: 스플래시부터 다시 뜨지 않고 오류 화면에 머문다.
- OS가 백그라운드 WebView 프로세스를 직접 종료한 경우: 이 변경으로 막을 수 없으며 기존
  `RouteKeeper`가 최근 경로를 복원한다.
- 진행 중 운동 세션: 별도 타이머 복원 설계에 따라 앱 재마운트 뒤 멈춘 상태로 보존되고,
  사용자가 `다시 운동하기`를 눌러 재개한다.

## 테스트

순수 함수 단위 테스트로 다음을 검증한다.

- 청크와 대표적인 네트워크 로드 오류는 자동복구 대상으로 분류한다.
- 일반 `TypeError`와 렌더 오류는 자동복구 대상으로 분류하지 않는다.
- 자동복구 대상도 30초 가드를 통과할 때만 새로고침할 수 있다.
- 저장용 진단 정보는 경로·메시지·digest·분류 결과만 포함하고 길이를 제한한다.

기존 `chunk-recovery`, `route-restore`, 앱 스플래시 테스트와 타이머 복원 테스트를 함께
실행해 청크 자가복구와 경로 복원 동작이 유지되는지 확인한다.
