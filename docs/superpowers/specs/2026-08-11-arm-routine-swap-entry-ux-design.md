# 팔 루틴 교환 진입 UX 개선 Design

## 배경

현재 운동 등록 화면은 교환 가능한 팔 일차마다 일차 헤더 오른쪽에
`팔 루틴 교환` 버튼을 표시한다. 교환은 두 일차에 걸친 관리 작업이지만 동일한
버튼이 여러 번 상시 노출되어, 일차별 운동 편집 기능보다 더 강하게 보이고 화면의
행동 위계가 흐려진다.

## 목표

- `팔 루틴 교환` 진입 버튼을 운동 등록 화면 상단에 한 번만 표시한다.
- 버튼을 누른 뒤 인라인 패널에서 첫 번째 일차와 두 번째 일차를 순서대로 고른다.
- 기존 교환 가능 조건, 저장하지 않은 변경 차단, 확인 대화상자, 서버 요청 및 오류
  처리는 그대로 유지한다.

## 범위 밖

- 팔 루틴 교환 규칙이나 서버 RPC 변경
- 루틴 설정 화면 변경
- 운동 추가, 추천, 저장 등 주변 편집 기능의 재설계

## 화면 배치

`또는 직접 등록` 행의 오른쪽 작업 영역에 `팔 루틴 교환`과
`전체 운동 초기화`를 함께 둔다. 교환 가능한 팔 일차 쌍이 없으면 교환 버튼은
표시하지 않는다. 각 일차 헤더에 있던 교환 버튼은 제거한다.

교환 버튼을 누르면 작업 행 바로 아래, 일차 목록 위에 인라인 선택 패널을 연다.
버튼을 다시 누르면 패널을 닫고 선택 상태를 초기화한다.

## 선택 흐름

1. 패널을 처음 열면 `첫 번째 일차`라는 안내와 함께, 다른 팔 일차와 교환 가능한
   일차만 칩으로 표시한다.
2. 첫 번째 일차를 고르면 선택된 칩을 강조하고 `두 번째 일차` 선택 영역을 같은
   패널에 표시한다.
3. 두 번째 영역에는 기존 `eligibleArmSwapTargets`가 반환한 일차만 표시한다.
4. 두 번째 일차를 고르면 기존 확인 대화상자를 연다.
5. 확인 대화상자를 취소하면 첫 번째 일차 선택은 유지하여 다른 대상을 고를 수 있게
   한다. 교환을 확인하면 기존 요청 및 성공 후 새로고침 흐름을 사용한다.
6. 첫 번째 일차를 다른 칩으로 바꾸면 두 번째 일차 후보도 즉시 해당 일차 기준으로
   바뀐다.

운동 추가 대상 선택 패널과 팔 루틴 교환 패널은 동시에 열지 않는다.

## 상태와 접근성

- 교환 요청 중에는 상단 교환 버튼과 모든 일차 선택 칩을 비활성화한다.
- 첫 번째 및 두 번째 일차 선택 영역은 의미가 드러나는 `role="group"`과
  접근성 이름을 갖는다.
- 선택된 첫 번째 일차 칩은 색상뿐 아니라 `aria-pressed`로도 상태를 전달한다.
- 좁은 화면에서는 상단 작업 버튼들이 줄바꿈될 수 있으며 일차 제목 영역을
  침범하지 않는다.

## 검증

- 교환 가능한 팔 일차가 여러 개여도 `팔 루틴 교환` 진입 버튼은 하나만 보인다.
- 교환 가능한 쌍이 없으면 진입 버튼과 선택 패널이 보이지 않는다.
- 버튼으로 패널을 열고 닫을 수 있으며 닫을 때 선택이 초기화된다.
- 첫 번째 일차를 고른 뒤 호환되는 두 번째 일차만 표시한다.
- 두 번째 일차 선택 후 기존 확인 문구와 교환 요청이 그대로 동작한다.
- 기존 저장하지 않은 변경 차단, 실패 메시지, 중복 요청 방지 테스트가 계속
  통과한다.
