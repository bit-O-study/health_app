# 운동 타이머 앱 재진입 복원 설계

## 문제

진행 중인 운동 타이머는 `localStorage`에 `startedAt`, `accumulated`,
`lastSeenAt`을 저장한다. 앱이 새로 마운트될 때 저장 상태가 실행 중이면 현재 구현은
타이머를 자동으로 다시 실행한다. 사용자가 운동 화면을 열지 않고 앱에 들어왔다가 몇 분
뒤 `다시 운동하기`를 누르면, 그 몇 분까지 운동시간에 포함되어 화면이 4분 등에서
시작할 수 있다.

`다시 운동하기`로 이전 운동시간을 보존하는 기능은 유지해야 한다. 문제는 저장된 시간을
복원하는 것 자체가 아니라, 사용자가 재개를 선택하기 전에 타이머가 자동으로 흐르는
것이다.

## 검토한 접근

1. **앱의 새 실행에서 저장된 실행 중 타이머를 자동 일시정지한다. (선택)**
   마지막 하트비트까지의 실제 활성 시간만 누적하고, 이후 시간은 사용자가
   `다시 운동하기`를 누를 때까지 세지 않는다. 기존 저장 형식과 재개 UI를 유지하면서
   문제의 원인만 제거한다.
2. 세션 상태에 `active`, `background`, `abandoned` 같은 수명주기 필드를 추가한다.
   상태를 더 정밀하게 표현할 수 있지만 저장 형식 마이그레이션과 여러 화면 변경이 필요해
   이번 문제에는 과하다.
3. 앱 진입 시 저장 타이머를 초기화한다. 구현은 단순하지만 이전 시간을 이어가는
   `다시 운동하기` 기능을 없애므로 요구사항에 맞지 않는다.

## 설계

`timer-store.ts`에 실행 중인 저장 상태를 앱 재진입용 일시정지 상태로 바꾸는 순수 함수를
추가한다.

- 입력이 없거나 이미 일시정지된 상태면 그대로 반환한다.
- 실행 중 상태면 현재 실행 구간에서 `startedAt`부터 `lastSeenAt`까지의 시간만
  `accumulated`에 더한다.
- 앱이 보이지 않았던 `lastSeenAt` 이후 시간은 더하지 않는다.
- 결과를 일시정지 상태로 반환한다.

`WorkoutSessionTimer`의 최초 복원 effect는 이 함수를 사용한다. 따라서 화면에는 기존
세션이 `다시 운동하기` 상태로 나타나지만 시간은 증가하지 않는다. 사용자가
`다시 운동하기`를 누르면 기존 `resume()`이 누적 시간을 보존하고 그 클릭 시점부터 새
실행 구간을 시작한다.

단, 운동모드에서 `운동법·꿀팁` 상세로 이동했다가 돌아오는 내부 화면 전환은 기존
`heltch.resumeWorkout` 세션 플래그로 구분한다. 이 경우는 사용자가 운동을 중단하거나
앱을 재실행한 것이 아니므로 자동 일시정지하지 않고, 기존처럼 운동모드와 실행 중
타이머를 바로 복원한다.

명시적으로 `운동 시작`을 누르는 흐름은 기존처럼 누적 시간을 0으로 초기화한다. 같은
마운트 안에서 운동 중 잠깐 화면을 잠그거나 다른 앱을 보는 흐름의 기존 10분 공백 정책은
이번 변경 범위에 포함하지 않는다.

## 데이터 흐름

1. 앱 마운트 → 저장된 타이머와 내부 상세복귀 플래그 읽기
2. 내부 상세복귀이면 기존 실행 상태를 유지하고 운동모드 자동 재오픈
3. 일반 복원이면서 실행 중 저장본이면 마지막 하트비트까지 누적 후 일시정지
4. 일시정지 상태 저장 및 `다시 운동하기` 표시
5. 사용자 탭 → 기존 누적값으로 재개, 클릭 시각부터 카운트

날짜가 바뀐 저장본은 기존 자정 롤오버 로직을 그대로 거친다. 롤오버 전에 일시정지 상태로
정규화하므로 앱이 닫혀 있던 시간이 이전 날짜 기록에 추가되지 않는다.

## 테스트

순수 함수 단위 테스트로 다음을 검증한다.

- 이미 일시정지된 타이머는 변경하지 않는다.
- 실행 중 타이머는 마지막 하트비트까지만 누적한다.
- 앱 재진입부터 사용자의 재개 클릭까지 흐른 시간은 누적하지 않는다.
- 운동 상세에서 자동복귀하는 경우에는 실행 중 상태를 유지한다.

기존 `reconcileResume` 테스트와 타이머 delta 테스트를 함께 실행해 백그라운드 공백 처리와
누적 저장 동작의 회귀가 없는지 확인한다.
